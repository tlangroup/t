# Everything is value —— T 语言版

> 本文是「一切皆值（everything is value）」设计文档的 **T 语言版本**，由原稿（某不熟悉 T 的 agent 所写、采用类 Zig 语法）改写而来。
>
> **改写要点**
> 1. **语法全部改为 T 约定**：`fn name(params) Ret { }`（返回类型前无 `->`）、`match (x) { pat => expr }`（表达式）、`var x: T = v` 绑定、`enum Color : u8 { ... }`、底类型跳转 `break` / `continue` / `return` / `panic`、以及 `unit` 类型与值 `()`。
> 2. **void 已被移除**：在「一切皆值」下不存在 void。为过渡，**`void` 暂时作为 `unit` 的别名**（类型与值同一）——旧代码 / 旧文档里的 `void` 一律按 `unit` 处理。
> 3. **在 T 中 `unit` 既是类型也是值**：类型写作 `unit`，其唯一值写作 `()``；`()` 可以像普通值一样被绑定、返回、传递，`unit` 可以像普通类型一样被标注。「unit」在语言里同时承担「类型」与「值」两种身份，这是 T 落「一切皆值」无例外的关键。
> 4. **「一切皆表达式」是本设计的核心主张**：`if` / `while` / `for` / 块 在本设计中统一为表达式。T 已实现两种迭代写法——计数式 `for (int i = 0; i < 5; i = i + 1)` 与遍历式 `for (x in arr)`（含区间 `for i in 0..5`），二者都作为表达式、都可带取值补全子句。循环取值补全的**机制**（`else` 完成子句）是必要且充分的：必要（值位置下缺它即类型不完备），充分（只要有它供值，循环在所有路径下都类型完备）。`else` 是该完成子句的*拼写*，机制本身无等价或补充方案；是否换专用关键字是可独立拍板的设计选择（见「设计注记：循环取值补全的备选方案」）。本文即按这套已确定的设计撰写。

## 五分钟速览

（本节只是地图，术语以正文定义为准）

一句话：一切皆表达式，类型由「最后算出的那个值」决定；空也是值（写作 `()`）；多个值相遇时**补齐**，值够不够看位置。

**先判位置（优先级最高）**

- **值位置**（右值、`return` 值、实参 / 字段、块尾、条件位）→ 必须类型完备，`else` 少不了。
- **语句位置**（分号结尾的非末位表达式）→ 可以不完备。
- 位置自上而下传导：块尾会把里面的循环升格为值位置。

**再看补齐（多候选如何合流）**

- 判据：存在一个能容纳全部候选的类型；只允许加宽，不允许收窄。
- 跨符号可加宽（`u8 + i16 → i16`），同宽不同符号报错（`i16 + u16`）；整型与浮点看尾数（`u24 + f32` 可，`u25 + f32` 不可）。
- `complex` 按分量补齐（`f64 + c64 → c128`）；`bool` 不与任何基础类型补齐。
- `Never` 是单位元（任意 + `Never` = 另一方）；`unit` 不进候选，落在一般值位置即报错，落在循环取值处则要求该循环带 `else`。

**期望类型优先**：各分支先向期望类型收敛，不是先补宽再兼容。

**循环**

- 值来源优先级：带值 `break v` ＞ 最后一次成功交付的尾表达式值 ＞ 不带值 `break` / 一轮都没成功交付 → `unit` → 触发 `else`。
- 「成功交付」指该轮尾表达式给出非 `unit` 的值；`continue` 跳走的轮次、产出 `()` 的轮次都不算交付，会被跳过。
- 静态看类型、动态看数据：`else` 要不要写由类型决定，值取哪一轮由数据决定。
- 无自然出口（`while (true) {}`）→ `Never`，不需要 `else`。
- 有没有值与容器空不空无关。

**块与跳转**

- 块尾无分号 → 值；有分号 → `unit`（值 `()`）；`var` 绑定返回 `unit`。
- `break` / `continue` / `return` / `panic` 同属一族底类型，兼容任意类型；`continue` 不带值。

四张速查表见「速查表」一节，术语以「术语表」一节为准。

## 一、总纲：一切皆表达式

在 T 里，没有「语句」与「表达式」的割裂——分支、循环、块，统统都是表达式，都能「算出」一个值。

连「空」也是值：T 设有 `unit` 类型，它唯一的字面量就是 `()`。所以「没有可用的值」不是例外状态，而是一种普通的值——只是它不携带信息。

这意味着：`if`、`match`、`while`、`for`、`{}` 都可以出现在赋值号右边，直接参与类型推断。理解这一点，后面所有规则都是它的推论。

> **T 专属：`unit` 即是类型，也是值**
> 在多数语言里，「类型」与「值」是两套词法。`unit` 在 T 里把二者合一：
> - `unit` 是**类型名**——你可以写 `var x: unit = ();`、`fn f() unit { ... }`。
> - `()` 是该类型的**唯一值**——它是一个货真价实的值，可以绑定、返回、传参、参与运算（例如作为 `match` 的一个臂结果）。
> - 因此「空」在 T 里从不是「无值」的真空，而是一个可被传递、被比较、被推断的具体值 `()``。「一切皆值」在 T 中没有例外。

## 二、分支表达式：类型的补齐与统一

规则：分支表达式（`if` / `match`）的整体类型，由各分支类型**补齐**得出——不再要求各分支类型完全一致，而是统一到一个各分支都能安全转换到的类型；无法补齐时编译报错。

正例：

```t
var n = if (true) { 10i8 } else { 1024i16 };       // i8 与 i16 补齐为 i16，n 为 i16
var s = match (1) { 1 => "one", _ => "other" };    // 各分支同为 str，整体为 str
```

易错点：

- **不再「必须一致」**：`i8` 与 `i16` 是允许的，会补齐为 `i16`；「补齐」与「必须一致」是两种策略，本语言采用前者。
- **`match` 仍需穷尽**：补齐解决的是类型差异，不解决漏分支——`match` 必须覆盖所有取值（见 `docs/syntax/drafts/match.md` 的穷尽性判据）。
- **不兼容的组合照样报错**：如 `i16` 与 `u16`，以及无法无损表示的整型与浮点组合（如 `u25` 与 `f32`），都直接失败。注意 `u8 + i16` 是合法的，会补齐为 `i16`。

**逐项对应（显式转换原语）**：T 的显式转换统一走 `@` 族原语（T 以 `@` 前缀标识内建原语），命名固定为「`@` + 目标类型 + `_from_` + 源类型」：

- 整型到浮点：`@float_from_int`
- 浮点到整型：`@int_from_float`（默认截断，变体 `@int_from_float_saturating`）
- 整型互转：按具体类型对命名，如 `@u8_from_i16`、`@i32_from_u8`
- 由实数构造复数：`@c64_from_f32`、`@c128_from_f64`

> 族名与类型名要分开：原语名里的 `int` / `float` 是**族名**（整型族 / 浮点族），不是类型名。T 的类型一律按 `i` 或 `u` 加字宽命名（`i8`~`i128`、`u8`~`u128`），`int` 是早期遗留写法、已从类型体系移除；正文与示例中的整型标注一律写 `i32`。跨族转换用族名，同族之间按具体类型对命名（如 `@u8_from_i16`）。
>
> **两源特例**：由实部与虚部构造复数有两个源，不套用上述单源形式，单列为 `@complex_from_parts(re, im)`。

**多候选归约**：

- 候选 ≥3 时整体求唯一解，不按书写顺序两两配对：`u8 + i16 + u32 → i32`。
- 归约与顺序无关（交换律成立）；只有「存在一个能容纳全部候选的类型」才算成功，任一对候选不可解即整体报错。

**阶段顺序固定**：先 `Never` 归约 → 再 `comptime_int` 让位 → 最后 primitive 阶梯；任一阶段收敛后不再回头放宽。

**越界与溢出**：

- 字面量越界在编译期报错：`var x: i8 = 300;` —— 300 放不进 `i8`，错误发生在编译期，与补齐无关。
- 补齐只统一类型，不管值放不放得下：1024 能合入 `i16` 是靠补齐；若两侧都是 `i8`，越界依旧报错。
- 运行期溢出：检查落在补齐后的目标类型上——安全构建（`Debug` / `ReleaseSafe`）下报错；非安全构建（`ReleaseFast` / `ReleaseSmall`）下按该类型的默认行为处理。

**语法骨架**：`else` 子句写在循环体之后，它属于循环本身，而不是循环体内某个 `if`。T 已实现两种迭代写法——计数式 `for (int i = 0; i < 5; i = i + 1)` 与遍历式 `for (x in arr)`（含区间 `for i in 0..5`），二者在本设计中都作为表达式、都可带 `else` 完成子句：

```
for (int i = 0; i < 5; i = i + 1) { 循环体 } else { 兜底 }   // 计数式（已实现）
for (x in arr) { 循环体 } else { 兜底 }                      // 遍历式（已实现）
for i in 0..5 { 循环体 } else { 兜底 }                       // 区间遍历（已实现）
while (cond) { 循环体 } else { 兜底 }
while (true) { 循环体 } else { 兜底 }
```
> 注：上例计数式写作 `for (int i = 0; ...)`，规范整型名下等价写成 `for (var i: i64 = 0; i < 5; i = i + 1)`，二者同义。

> **循环取值补全的*机制*是必要且充分的**：所谓「必要且充分」，指的是**「一个在「循环未交付值」时供值的完成子句」这一机制本身**——它让循环作为表达式在「交不出可用值」时仍能给出完备类型，且只要有它、循环在所有路径下都类型完备，无需别的补全语法。
> - **必要**：值位置下，只要存在「交不出可用值」的路径（尾表达式落 `()`、只有不带值 `break`、或尾位置是 `continue`、或零轮迭代），就必须有该完成子句，否则类型不完备、编译报错。
> - **充分**：只要有它供值，循环在**所有**路径下都类型完备——无论容器是否为空、无论哪一轮交付值、无论是否中途 `break`，都不需要额外的补全语法。
>
> **`else` 是这个完成子句的*拼写*，而非唯一可能的写法**：本设计采用 `else`，是因为它与 Python 既有的 `for/while ... else`（「未 break 时执行」）语义同构、只是改为返回值；但 `else` 重载了 `if`/`match` 的「否则」含义，正是 Python 该语法长期被诟病之处。若从零设计，用专门的完成子句关键字（如 `default` / `or` / `then`）可避免歧义——**机制不变，只是换词**。详见「设计注记：循环取值补全的备选方案」。

`else` 的触发条件只有两种：零轮迭代（容器为空），或是循环整体交不出可用的值，即：尾表达式的值是 `()`、只有不带值的 `break`、或尾位置是 `continue`。逐条判定见规则二、规则三。

> **设计注记：循环取值补全的备选方案**
> 本设计选 `else` 作完成子句，但「一切皆值」并不*必然*推导出 `else` 这一个解。把**机制**与**拼写**拆开看：
> - **主流事实标准恰是反面**：Rust / Kotlin / Go / Swift 等偏「一切皆表达式」的语言，普遍让 `for`/`while` 仍是语句（返回 `()`/`Unit`），聚合值交给 `fold`/`collect`、可变累加器或迭代器组合子；只有 Rust 的 `loop { break v }` + `Never` 把「无限循环」做成值表达式。也就是说，「循环也是值表达式」本身就不是业界默认，更谈不上 `else` 是某种"标准答案"。
> - **若坚持「循环也是值表达式」，完成子句的机制绕不开**：循环可能零轮或全程不交付值，又不允许 `unit` 泄漏进值位置，就*必须*有某个子句在无值路径上供值——这即「`else`（或更中性的名字）是必要的」的由来；它一旦存在就覆盖全部无值路径，故「充分」。
> - **`else` vs 专用关键字的取舍**：`else` 复用程序员已熟悉的「未 break 即走 else」直觉（源自 Python）、零新增关键字；坏处是它已是 `if`/`match` 的「否则」义词，嵌套时「悬空 else 归谁」的歧义被放大（见上「语法歧义」段）。专用关键字（`default`/`or`/`then`）表达力相同、可读性更稳，但要引入保留字。这是拼写层权衡，不影响机制正确性。
> - **另一条路：不为 `for`/`while` 求值，只让 `loop` 求值**：即 Rust 做法——普通 `for`/`while` 仍是语句（返回 `unit`），另设永远需要 `break v` 收口的 `loop` 表达式；`while (true) {}` 类是 `Never`。代价是「一切皆值」在循环上开例外（普通循环不是值），与本文总纲冲突，故未被采用。
> 结论：在「所有循环都是值表达式」的约束下，`else` 完成子句（机制）确实必要且充分；`else` 作为*拼写*是合理的默认，但并非无争议的最优——是否换专用关键字是可独立拍板的设计选择。

## 三、类型补齐规则

总则：同一位置出现多个候选类型时，不报错，而是寻找一个所有候选都能安全转换（`coerce`）到的类型，该类型即表达式整体类型。补齐是单向向上的过程——只允许加宽，不允许收窄。

「不报错」有两个例外：`Never` 是单位元，不与任何候选竞争，直接让位给另一方；`unit` 不进候选——它代表的不是「不够宽」，而是「没有可用值」的标记，因此既不参与竞争、也不走补齐失败那条路径，而是交给兜底检查单独判定（见「与 unit、Never 的关系」）。

候选范围不限于 primitive，但要按「值类型 / 引用类型」分开对待：

- **值类型**（数组 / 元组 / 可选）可以递归：先要求结构一致，再逐层递归到元素层，元素层按下面的 primitive 阶梯判定；结构不一致则补齐失败。可选类型先比较其内部类型，补齐结果仍是可选类型。
- **引用类型**（指针 / 切片）不递归，只按同一性补齐：指向类型（切片为元素类型）必须完全相同，不做任何元素层加宽。

为什么引用类型不能递归：指针与切片的值是地址，元素类型一改，读写宽度就跟着改——`*i8` 与 `*i16` 若合流为 `*i16`，解引用会读写两个字节，而原对象只有一个字节，这是静默写穿。整型加宽是把值搬进更宽的盒子；引用类型「加宽」是改变了盒子的尺寸定义，前提根本不成立。切片同为胖指针，元素步长一变，危险与指针相同；数组则是值类型，合并只是把值搬宽，可以递归。

- **可变性与对齐按单向收敛**：`*T` 与 `*const T` 收敛到 `*const T`——只读约束可以变严、不可以变松；`*align(a) T` 与 `*align(b) T` 取更严格（更大）的那个对齐，不得取更松者，否则会出现未对齐访问。方向写反即报错。
- 要改变指向类型必须显式：`*i8 → *i16` 这类转换一律走 `@` 族原语，不静默发生。
- **可选不是豁免通道**：内部裹着指针或切片时，仍受上面「同一性」一条的约束。

本节以下的阶梯只描述 primitive 层的判据。

**适用范围**：

- 分支表达式：`if` / `match` 的各分支；
- 循环的取值来源：`break` 值、末轮尾表达式值、`else` 值三者之间；
- 带多个 `break`、且各 `break` 返回类型不同的块；
- 集合字面量：数组 / 元组元素；
- `u54 + c128 → 报错`，需显式转换。

**高阶浮点与复数无法补齐**：本语言的复数只到 `c128`（分量为 `f64`，尾数 53 位），因此 `f80` / `f128` 与任何复数都只能报错——这是梯度不齐所致，不是取向取舍；若要放开，需引入分量更大的复数类型。

**不另立规则**：`Never` 仍是补齐的单位元；`unit` 不进候选，按兜底检查处理（规则见下文「与 unit、Never 的关系」）。

**复数字面量与构造**：

- 复数由实部与虚部两个分量构造，两分量各自套用实数侧的补齐规则，再落到目标复数类型的分量类型（`c64` 用 `f32`、`c128` 用 `f64`）。
- 例：分量给 `u24` 与 `f32` → 可构造 `c64`（`f32` 尾数 24 位）；给 `u25` → 报错。
- 不设复数专用字面量：不存在类似 `10i8` 的「复数后缀」，复数一律由构造原语产生。
- 单分量构造：`@c64_from_f32`、`@c128_from_f64`——把实数放入实部、虚部补零，沿用 `@` + 目标类型名 + `_from_` + 源类型名的约定。
- 双分量构造：`@complex_from_parts(re, im)`——源是两个分量，故按特例命名；两分量先行按实数补齐统一，再整体落到目标复数类型的分量类型。

**非数值 primitive**：

- 同类型 → 取本身（`str + str → str`、`bool + bool → bool`、`unit + unit → unit`）；
- `bool` 与任何其它基础类型都无法补齐：`bool + i32`、`bool + str`、`bool + f32` 等一律报错；
- `unit` 不走补齐，而走兜底检查：它不进候选集，判定规则见「与 unit、Never 的关系」一节；
- 不同 primitive 类型之间没有公共超类型 → 补齐失败，报错。

**与 unit、Never 的关系**：

本语言设有 `unit` 类型：它唯一的字面量是 `()`。凡「没有可用的值」之处，得到的就是 `unit` 的 `()``——不是「无值」，而是「值不携带信息」。`unit` 不进入补齐的候选集：它既不能与其它类型合流，也不会把别的候选拉高或拉低。

> **T 专属重申**：`unit` 在 T 里**既是类型也是值**。`unit` 是类型名，`()` 是该类型的唯一值；二者可互换地参与语言机制——`()` 可被绑定、返回、作为 `match` 臂结果，`unit` 可被标注为类型。正因为「空」在 T 里是一个具体的值 `()``，「一切皆值」才没有任何例外分支。

`unit` 走的是兜底检查，而不是补齐：

- 只与 `unit` 相遇、或所在位置期望就是 `unit` → 结果即 `unit`（值 `()`）；
- 出现在循环的取值来源（尾表达式、`break` 值、`else` 值之间）→ 表示「这一路交不出可用值」，不进候选，但强制该循环带上 `else`；
- 出现在其它值位置（右值、实参、块尾、条件位）且该位置并非 `unit` → 硬错误，如 `var x: i32 = if (c) { 1 } else { () };`。

**期望类型与显式转换**：

- **期望类型优先于补齐**：各分支先各自向期望类型收敛，而不是先补成一个更宽的类型再回头兼容。因此 `var x: u8 = if (c) { 1 } else { 300 };` 报错的原因是 300 放不进 `u8`，而不是「补齐成了 `i16`」。
- **补齐 ≠ 隐式转换**：补齐管的是多候选消歧（同一位置有 ≥2 个候选，求它们共同可转换到的类型）；单值向期望类型的加宽是另一套机制（如 `var x: i16 = 1i8;`，是否合法由 `coerce` 规则决定，不归补齐）。两者边界要分开写、分开展报错。
- **补齐失败后的出口**：报错时应给出对应的显式转换建议，用 `@` 族原语（命名见上文「逐项对应」）。
- 默认行为是保守截断：与显式转换同一口径，不静默回绕；需要别的行为须走显式转换，变体只有 `_wrapping`（回绕）与 `_saturating`（饱和）两档。
- 运算符本身不另立变体符号：回绕与饱和不以符号后缀的形式挂在 `+` / `-` / `*` 上。

**补充：编译器可补入的对等分支**：

某些构造下，编译器会把隐含分支（如 `catch` 的非错误分支；`catch` 属错误处理语法，本文不展开）也视为参与解析的对等类型；否则只按显式分支解析，会得到 `comptime_int` 并因「依赖运行时控制流」而报错。

### 整型补齐

- 标准阶梯：`i8 → i16 → i32 → i64 → i128`、`u8 → u16 → u32 → u64 → u128`；另有指针宽度的 `isize` / `usize`。
- 支持任意位宽（如 `i7`、`u24`），最大位宽 65535。
- 判据是「目标类型能表示源类型的全部值」，因此允许跨符号加宽：
  - `u8 + i16 → i16`（合法：`i16` 装得下 255）
  - `u16 + i32 → i32`（合法）
  - `i16 + u16 → 报错`（同宽度、互不覆盖）
- `comptime_int`（编译期整型）：无后缀整数字面量的类型就是它；补齐时按无损容纳判据处理——具体整型若能无损容纳该字面量值，就让位给具体类型。这正是「无后缀字面量取上下文期望类型」的机制本体；在归约顺序上它紧随 `Never` 之后、先于 primitive 阶梯消解。

### 浮点补齐

- 阶梯：`f16 → f32 → f64 → f80 → f128`。
- 整型与浮点：除「无损」情形外一律报错，判据是尾数位数：
  - `u24 + f32 → 合法`（`f32` 尾数 24 位，能无损容纳 `u24`）
  - `u25 + f32 → 报错`，需显式 `@float_from_int`
  - `i8 + f32 → f32`

### 复数补齐

- `complex` 同为 T 的 primitive 类型，按分量定义：
  - `c64` —— 实部、虚部各为 `f32`
  - `c128` —— 实部、虚部各为 `f64`
- 规则与实数同构，判据仍是「能表示源类型的全部值」，只是要落到分量上：
  - 复数之间：`c64 → c128`，判据是分量能无损表示。
  - 实数与复数：复数支配实数，但受分量精度约束：
    - `f16` / `f32 + c64 → c64`
    - `f64 + c64 → c128`（`c64` 分量为 `f32`，容不下 `f64`，必须升档）
    - `f64 + c128 → c128`
  - 整型与复数：判据延伸到分量，与整型对浮点完全同构：
    - `u24 + c64 → c64`（`f32` 尾数 24 位）
    - `u25 + c64 → 报错`，需显式转换
    - `u53 + c128 → c128`（`f64` 尾数 53 位）
    - `u54 + c128 → 报错`
    - `f80` / `f128` 与任意复数 → 报错（梯度不齐）

### 二元运算的两侧操作数

- 算术（`+ - * /`）与按位（`& | ^`）运算参与补齐；
- 移位是特例——被移位数与移位量各自独立定型，不参与同一套补齐；
- 比较运算（`==` `<` 等）两侧按补齐统一，但结果恒为 `bool`；
- 高阶浮点与复数（见上）无法补齐。

### 溢出与转换的变体：命名方式

- **挂载点不同**：某些语言把变体做成运算符的符号后缀（回绕为 `%`、饱和为 `|`）；T 把变体做成原语名的词尾后缀，接在「`@` + 目标类型 + `_from_` + 源类型」之后，写 `_wrapping` 或 `_saturating`。
- **T 为什么放词尾**：`@` 族是 T 唯一的显式转换入口，原语名里已经带着「目标是谁、源是谁」的完整方向信息；变体只改行为、不改方向，接在名字末尾最自然，一眼就能读出「把哪个类型转成哪个类型、按哪一档做」。
- **运算符后缀做不到同样的事**：符号后缀只能描述同类型自运算，一旦两个类型宽窄不同，符号里就没有位置安放方向。
- **覆盖范围不同**：饱和只覆盖加、减、乘（含一元取反），没有饱和除法、取余与移位；T 的后缀跟在原语之后，凡是走 `@` 族的转换都能挂上同一套变体，不受运算符种类的限制。
- **默认档的取向不同**：某些语言默认运算符越界即错（安全模式 panic，快速模式未定义行为），想要静默必须显式换符号；T 默认是保守截断，想要别的行为才显式加后缀。
- **checked 那一档的落点不同**：某些语言不设第三个后缀，而是用返回值表达——内置函数返回带溢出位的结构体，标准库返回 error union；T 只提供两档，越界检查不单列原语，报错建议由补齐失败时的提示给出。
- **转换函数侧的分工也不同**：某些语言的 `@intCast` 与 `@truncate` 是「检查 / 不检查」的二分，本身不带变体；T 把「检查与否」压成默认值加两个后缀，转换原语只有一族、一套形状。

### 告警等级随构建模式细分

- **构建模式只调等级，不改语义**：它不影响类型判定与运行行为，只决定某条诊断是否出现、以哪个等级出现。
- **错误级不降级**：`unit` 落在一般值位置、补齐失败这类错误，在任何构建模式下都是报错——不会因为选了发布构建就放行。
- **告警级随模式升降**：`Debug` / `ReleaseSafe` 下报为告警，`ReleaseFast` / `ReleaseSmall` 下静默，以免阻塞发布；想重新看到，切回 `Debug` 或 `ReleaseSafe`。
- **显式忽略与模式无关**：`_` 开头命名、`_ =` 显式丢弃，在任何模式下都表示「有意忽略」，不再产生任何等级。
- 若日后引入比告警更低的「提示」类，按同一梯度处理：只在 `Debug` 下出现。

> 目前已知的告警有「未使用变量」与「不可达代码」两条，其余待逐条归类。

## 四、循环表达式的返回值规则（重点）

循环也是表达式，但它是否「必须产出值」，取决于它出现的位置。

正例：

```t
var a: i32 = while (true) { break 42; };                                       // 值位置；来源：break 带值
var b: i32 = while (true) { break 99; };                                       // 值位置；来源：break 带值
var c: unit = for i in 0..5 { print(i); };                                     // 值位置且期望 unit；来源：尾表达式产出 ()
var nl: i32 = while (true) { };                                                // 无自然出口 → 类型 Never；作为右值可兼容 i32，此表达式永不返回；无需 else
var g: i32 = for (int i = 0; i < 10; i = i + 1) { if (i == 5) { break i; } } else { -1 };   // 值位置；来源：break 值优先（计数式 for 同样可带 else）
var arr = [1, 2, 3, 4];
var res: i32 = for x in arr { if (x > 2) { x } else { () } } else { 0 };       // res = 4
var d: i32 = for x in arr { x * 2 } else { -1 };                               // 值位置；来源：最后一次成功交付（x = 4）得 8
```

注意 `for (x in arr)` / `for (int i = 0; ...)` 中的循环变量与后文同名 `var` 处于不同作用域，但阅读时极易混淆，建议改名。

易错点：

- **`unit` 不是底类型**：`unit` 是「只有一个值 `()`」的普通类型，它不进候选集，也不能充当「任意类型」；出现在需要别的类型的一般值位置就是硬错误，落在循环的取值来源处则只是「这一路没有可用值」，触发 `else`。它与「底类型与跳转原语」一节里的 `Never` 是两回事，切勿混同。
- **值位置几乎总要写 `else`**：非空性推不出有可用值，`else` 承担的是「静态补全」职责，而非仅处理空数组。
- **`break` 是底类型，但不带值仍会走 `else`**：底类型说的是它自身在分支位置不与其它分支争类型（如 `if (c) { x } else { break; }` 中该 `if` 的类型仍是 `x` 的类型）；而循环的结果看的是「有没有值被带出」——不带值的 `break` 不交付值，循环落 `unit`，依然触发 `else`。
- **`continue` 不允许带值**：它不终止循环，没有接收方，因此它不参与「值的来源」。

### 规则一：先看位置

- **值位置**（作为右值被使用）：循环必须给出值，类型必须完备；只要存在「交不出可用值」的路径，`else` 就是必需的。
- **语句位置**（值被丢弃）：循环纯为副作用执行，不需要 `else`。
- **期望类型为 `unit` 的值位置**：如 `var c: unit = for i in 0..5 { print(i); };`，循环体尾表达式本身产出 `()`，与期望类型一致，`else` 可省。

这条规则与 `if` 完全对称：值位置必须补全每个分支，语句位置可以省略 `else`。统一为一句话——**值位置的表达式必须类型完备，语句位置可以不完备**。

### 位置的判定：哪些位置是值位置

**值位置**（表达式必须类型完备）：

- `var` / 赋值的右值；
- `return` 携带的值、函数体的末表达式；
- 函数调用与构造式的实参 / 字段值；
- 块的尾表达式；
- 条件位（`if` / `while` 的条件、`match` 的被匹配值）。

**语句位置**（值被丢弃，可以不完备）：

- 以分号结尾、且不是块尾的表达式语句；
- 循环 / 分支整体作为独立表达式语句出现时（如 `for i in 0..5 { print(i); };`）。

**传导规则（最容易踩）**：位置是自上而下传导的——

- 块尾表达式决定块类型，所以块尾是值位置：`var x = { for i in 0..n { print(i); } };` 里那个循环已被升格为值位置，必须有 `else`；加上分号变成 `{ for i in 0..n { print(i); }; }` 后就回到语句位置，`else` 可省。
- 一块整体处在语句位置时，它内部的非末位表达式也都在语句位置。

易错点：

- **分号是位置开关**：同一段循环，一个分号之差就决定「必须完备」还是「可以不完备」，同时把块的类型从尾表达式给出的值变成 `unit`。
- **期望 `unit` 的值位置仍是值位置**：它可省 `else`，理由不是「它处在语句位置」，而是循环体产出的 `()` 与期望类型一致——位置判定与类型判定是两件事，不要用后者去解释前者。

### 规则二：值的来源与优先级

- **带值 `break v`**：直接取 `v`，优先级最高；循环结果即 `v` 的类型，不触发 `else`。
- **不带值 `break`**：终止循环但不交付值，循环结果落 `unit`（值 `()`），触发 `else`。
- **自然跑完**：取最后一次成功交付的那一轮的尾表达式值。这里的「交付」指该轮尾表达式给出非 `unit` 的值；`continue` 跳走的轮次与产出 `()` 的轮次都不算交付，会被跳过。
- **`continue` 落在尾位置**：该轮不交付值、被跳过，不影响取值——即使它恰好是最后一轮，前面成功交付过的值依然有效。只有当所有轮次都没交付过值时，循环整体才落 `unit`、触发 `else`。
- **皆无值**：循环整体产出 `unit`，触发 `else`。
- **无自然出口的循环是 `Never`**：`while (true) {}` 这类永不自然结束的循环，类型是 `Never`（底类型）而非 `unit`——它不可能「落空」，因此不需要 `else`；而 `while (true) { if (c) { break 1; } }` 有出口，回到上一条常规判定。
- **`break` / `continue` 的语法**：标签怎么写、能不能带值、跨层怎么裁决，见「底类型与跳转原语」一节中的「跳转原语：break / continue」。

### 规则三：有没有可用值由循环体与 break 决定，与容器是否为空无关

数组非空不代表循环一定交出可用值，非空只保证「至少跑一轮」，却不保证哪一轮真的交付了值。

- **恒落 `()` 例**：`for x in arr { print(x); }` —— 数组非空，但尾表达式是调用，每轮都产出 `()`，没有任何一轮交付过值。
- **中间成功、末轮落空例**：`var arr = [1, 2, 3, 1]; for x in arr { if (x > 2) { x } else { () } }` —— 只有 `x = 3` 那一轮交付了值，整体取 3；把末位由 1 改成 4（数组变成 `[1, 2, 3, 4]`）则取 4。可见结果由「最后一次成功交付」决定，末轮是否落空不影响取值。

结论：`else` 的门槛是「静态可知拿不到可用值」，它有两个独立入口——零轮迭代（容器可能为空）与尾表达式的值落到 `unit` 的 `()``（循环体可能落空）。「需不需要 `else`」由类型静态判定，「值取哪一轮」由数据动态决定，两条线彼此独立；这也说明非空性推断无法替代 `else`。

> **语法歧义：`else` 归谁——就近绑定（定稿）**
> `else` 一律绑定最近的未闭合结构。`for x in arr { if (c) { a } else { b } }` 中那个 `else` 属于 `if`，不属于循环。当循环体末尾恰好是一个缺 `else` 的 `if` 时（如 `for x in arr { if (c) { a } } else { b }`），`else` 仍归 `if`——悬空 `else` 就近解析，不是「外层优先」。代价要写清：按这条口径，上例中的循环就没有 `else` 了；若它处在值位置且尾表达式可能落空，编译器据此报「缺 `else`」。想给循环配 `else`，就得先把那个 `if` 补完整，或把循环体包进显式块。想让 `else` 归循环，循环体必须自成完整结构；建议这类嵌套直接拆变量或加显式块，不要依赖阅读时的脑内解析。

### 表 2：循环判定表

| 位置 | 值的来源 | 需要 else | 结果类型 |
|---|---|---|---|
| 值位置 | 带值 `break v` | 否 | `v` 的类型 |
| 值位置 | 最后一次成功交付的尾表达式 | 是（存在无值路径时） | 尾表达式的类型 |
| 值位置 | 不带值 `break` / 始终未成功交付 / 皆无 | 是 | 由 `else` 供值 |
| 值位置 | 无自然出口（`while (true) {}`） | 否 | `Never` |
| 值位置、且期望 `unit` | 任意 | 否 | `unit` |
| 语句位置 | 任意 | 否 | `unit`（值被丢弃） |

## 五、底类型与跳转原语

规则：`return`、`panic`、`break`、`continue` 等跳转表达式的类型是 `Never`（底类型），它兼容任意类型；因此分支里出现跳转表达式时，无需显式写全类型。

正例：

```t
fn demo() i32 {
    var x = if (true) { 100 } else { return 0; };   // else 分支是 return，兼容 i32；x 为 i32
    match (x) { _ => panic("err") }                 // panic 兼容任意类型
}

var s: i32 = for x in arr { if (x > 3) { break x; } };  // 分支含 break，不破坏类型统一
```

易错点：误以为分支类型必须显式写全；实际上只要有一个分支是 `Never`，它就能「补位」任意类型。

注意：底类型管的是分支层面的类型统一，与「循环表达式的返回值规则」一节讲的「循环结果是否落 `unit`」是两件事——`break` 是底类型，但不带值时循环结果依然是 `unit`。

**补充：跨层跳转**

`break 'outer v` 从内层直接跳出到外层时，内层循环是被中途跳走的、并未自然产出值，其类型记为 `Never`（而非 `unit`），这样外层无需为一个「永远不会正常返回的内层循环」补 `else`；外层正常拿到 `v`，其 `else` 不执行。

### 跳转原语：break / continue

语法：

```
break     label?  value?
continue  label?
```

说明：`break` 可选标签、可选值；`continue` 可选标签、不允许带值。

规则：

- 标签是独立命名空间，只能指向词法上包围自己的循环；建议标签使用独立词法前缀（如 `'outer`），以便与普通标识符区分——否则 `break x` 无法判断 `x` 是标签还是返回值。
- `break 'L v` 中，`v` 的类型必须与循环 `L` 在值位置的期望类型统一。
- 若目标循环处于语句位置，`break` 不得带值（值无处安放）。
- `continue` 不携带值：它不终止循环，没有接收方。

**跨层跳出的组合裁决**：外层处于语句位置时，`break 'L v` 同样不得带值（值无处安放）；内层被中途跳走时，其类型记为 `Never`（而非 `unit`），外层无需为它补 `else`。

**`while` / `loop` 同样适用**：跨层跳出记 `Never` 的结论不限于 `for`。

**四个跳转原语的分工（语言把跳转统一为同一族）**：

- `break` —— 跳出循环 / 块，可带值；
- `continue` —— 跳到下一轮，不带值；
- `return` —— 本质是「`break` 出函数」，可带值；
- `panic` —— 永不返回，无接收方。

语言只保留一族跳转原语，且它们都是底类型，天然可在任意位置补位。

**与循环规则的接缝**：

- `break` 无值 → 循环结果落 `unit` → 触发 `else`；`break 'L` 值 → 循环结果即该值的类型 → 不触发 `else`。
- `continue` 落在尾位置时，该轮不交付值、被跳过；取值看的是最后一次成功交付的那一轮，它落在末轮也一样。

### 表 3：跳转原语对照表

| 原语 | 带值 | 带标签 | 目标 | 类型 |
|---|---|---|---|---|
| `break` | 可 | 可 | 循环 / 块 | `Never` |
| `continue` | 不可 | 可 | 循环下一轮 | `Never` |
| `return` | 可 | 不可 | 函数之外 | `Never` |
| `panic` | 不可 | 不可 | 永不返回 | `Never` |

## 六、块与绑定：末表达式决定块类型

规则：

- 块结尾无分号 → 返回该表达式的值。
- 块结尾带分号 → 返回 `unit`（值 `()`）。
- `var` 绑定本身返回 `unit`（值 `()`）。

正例：

```t
var d: i32 = { var t = 5; t + 3 };       // 末表达式 t+3 无分号，块为 i32
var e: unit = { var t = 5; t + 3; };     // 末表达式带分号，块为 unit（值 ()）
var f: unit = var x = 10;                // var 绑定返回 unit（值 ()）
```

易错点：漏写或多写分号会导致类型静默变化——一个是 `i32`，一个是 `unit`，往往只差一个分号。另注意 `var f: unit = var x = 10;` 中 `x` 属于未使用变量：当前口径为默认告警，允许用 `_` 开头命名、或用 `_ =` 显式丢弃来表示「有意忽略」。告警等级随构建模式细分——`Debug` 与 `ReleaseSafe` 下出现，发布构建下静默，等级表见「速查表」中的表 4。

> **T 专属**：`var` 绑定返回 `unit` 的 `()``，而 `unit` 既是类型也是值——所以「声明一个变量」这个动作本身也有一个可被传递、被推断的值 `()``，没有「无值语句」这种真空状态。这正是「一切皆值」在 T 中的体现。

## 七、与 Zig 0.16 的对照（T 改写版）

设计取向一致的：

- **`Never` 参与补齐**：底类型充当补齐的单位元，与对照语言一致。
- **判据取「能安全转换到的类型」**：不引入「最小上界」这类集合论术语，只要求存在一个各候选都能 `coerce` 过去的类型。
- **补齐范围覆盖复合类型**：值类型（数组 / 元组 / 可选）同样参与，按结构递归到元素层。

实现路径不同、结果等价的：

- **循环缺 `else` 的报错方式**：对照语言不写 `else` 会自动补一个求值为 `void` 的空子句，于是循环结果被解析为 `void`、在使用处报类型不匹配；T 则让循环结果直接落 `unit`，而 `unit` 不进候选、在不期望 `unit` 的位置就是硬错误，于是同样在不该出现 `unit` 的地方报错。两条路径不同，最终都报错，行为等价，差异只在表述层面。
- **「不携带信息」的表达方式**：对照语言的 `void` 与 T 的 `unit` 属于同一类「不携带信息」的类型，差别在名称与写法；T 给它配了字面量 `()``，因此「一切都是值」没有例外。

**T 的 void 处理（本设计定稿）**：

- **T 中不存在 `void`**。在「一切皆值」下，「某处没有值」这种状态被彻底取消——空也是值，写作 `()``。
- **过渡期别名**：为兼容旧代码 / 旧文档，`void` 暂时作为 `unit` 的别名——既指代类型 `unit`，也指代值 `()``。凡旧代码写 `void` 处，按 `unit` / `()` 处理即可，语义不变。
- **`unit` 既是类型也是值**：对照语言里 `void` 只是类型、不是值（没有 `void` 字面量）；T 的 `unit` 则不同——`unit` 是类型名，`()` 是该类型的唯一值，二者都能在语言机制里被当作「类型」或「值」使用。`unit` 因此没有「有类型无值」的尴尬，也让「一切皆值」在语法与语义上彻底贯通。

本语言按自身梯度推出的结论：

- **字面量后缀**：`10i8` 这类写法对照语言没有，靠对等类型推断或 `@as` 表达；T 直接用字面量后缀定型。
- **`unit` 取代了「无值」这一例外**：语言里不再有「某处没有值」这种状态——空也是值，写作 `()``；代价是「有名无值」的类型（如旧的 `void`）不再存在，凡出现即是一个值。
- **整型与浮点按尾数位数判无损**、以及 `f80` / `f128` 与复数因梯度不齐而报错，都是 T 自己的档位安排。

## 九、术语表

| 术语 | 含义 |

| 值位置 | 表达式必须类型完备的位置（右值、`return` 值、实参 / 字段、块尾、条件位） |
| 语句位置 | 值被丢弃的位置（分号结尾的非末位表达式） |

| 单位元 | 与任意类型补齐都得到另一方的元素 |
| `comptime_int` | 无后缀整数字面量的类型；补齐时按无损容纳让位 |

## 十、易错点速查小结

- **分支**：各分支类型允许补齐（如 `i8 + i16 → i16`、`u8 + i16 → i16`），统一到各分支都能安全转换到的类型；不兼容组合（`i16 + u16`、无法无损表示的整型 + 浮点）直接报错；`match` 必须穷尽。
- **补齐**：判据是「目标类型能表示源类型的全部值」，因此允许跨符号加宽；浮点看尾数（`u24 + f32` 合法，`u25 + f32` 报错）；`complex` 是 primitive，按分量补齐（`f64 + c64 → c128`），而 `f80` / `f128` 与复数无法补齐、直接报错；候选不限于 primitive——值类型（数组 / 元组 / 可选）按结构递归到元素层，引用类型（指针 / 切片）只按同一性补齐、不做元素层加宽（`*i8 + *i16` 报错），可变性向 `const` 收敛、对齐取更严格者；`bool` 与任何其它基础类型都无法补齐，`unit` 则完全不进候选（一般值位置报错，循环取值来源处要求 `else`）；候选 ≥3 时整体求唯一解、与书写顺序无关。
- **位置**：块尾、右值、`return` 值、实参 / 字段、条件位是值位置，必须类型完备；分号结尾的非末位表达式是语句位置，可不完备；位置自上而下传导——块尾的循环已被升格为值位置，`else` 省不得。
- **二元运算的两侧操作数**：算术（`+ - * /`）与按位（`& | ^`）运算参与补齐；移位是特例——被移位数与移位量各自独立定型，不参与同一套补齐；比较运算（`==` `<` 等）两侧按补齐统一，但结果恒为 `bool`。
- **循环**：先看位置——值位置须类型完备、`else` 必需；语句位置无需 `else`。值的来源：带值 `break` ＞ 最后一次成功交付的尾表达式值 ＞ 不带值 `break` / 始终未成功交付 → `unit` 触发 `else`（`continue` 跳走的轮次与产出 `()` 的轮次都不算交付，会被跳过）；无自然出口的循环（`while (true) {}`）是 `Never`，不需要 `else`。有没有可用值与容器是否为空无关。**循环 `else` 是必要且充分的**：它完整解决循环作为表达式的取值补全，没有别的等价或补充机制。
- **跳转**：`break` / `continue` / `return` / `panic` 同属一族底类型；其中只有 `break` 与 `continue` 可带标签（如 `break 'L v`），`return` 与 `panic` 不可带标签，`continue` 不允许带值；`return` 即 `break` 出函数，`panic` 永不返回。
- **`unit` ≠ `Never`**：没有可用值之处得到的是 `unit` 的 `()``，它是普通类型、不进候选；`Never` 是底类型，兼容任意类型，两者切勿混同。
- **`unit` 在 T 中既是类型也是值**：`unit` 可作类型标注，`()` 可作值被绑定 / 返回 / 传递；「空」是一个具体的值 `()``，不是真空状态——这是 T 落「一切皆值」无例外的根基。
- **底类型**：`return` / `panic` / `break` / `continue` 兼容任意类型，无需写全分支。
- **块**：末表达式分号有无，决定是交出尾表达式的值还是 `unit`，一字之差。
- **`void` 已移除**：T 无 `void`；过渡期 `void` 是 `unit` 的别名（类型与值同一），旧代码里的 `void` 按 `unit` / `()` 处理。
- **记住一句话**：在 T 里，一切皆表达式，一切皆值——连空都是值（`()``），类型由「最后算出的那个值」决定；而 `unit` 让「值」与「类型」合二为一，使得「一切皆值」没有任何例外分支。

#### A.3.1 desugar 姿势（只允许 A）

**姿势 A（采用）**：不新增求值原语，全部脱糖为既有节点。

- **值 `if`**：`var x: T = if (c) { A } else { B };` → 直接 lowering 为「条件分支 + 结果槽赋值」（复用 `"assign"` 节点）；语义等价于 `match (c) { true => A, false => B }`，与既有 `match` 表达式同构。
- **值 `for`/`while`（含 `else` 与 `break v`）**：desugar 为「累加器 + 已交付标志」，纯复用 `var`/`if`/`for`：
  ```
  var __r: T;                       // T = 交付类型与 else 类型的 lub
  var __delivered: bool = false;
  for (x in arr) {
      // 本轮「成功交付」= 尾表达式非 unit
      if (<本轮交付>) { __r = <尾表达式值>; __delivered = true; }
  }
  if (!__delivered) { __r = <else 值>; }   // else 完成子句
  // break v 脱糖为：__r = v; __delivered = true; break;
  var r: T = __r;
  ```
- **`unit`/`()`、`@` 转换原语、`Never` 跳转**：全部复用既有，无新节点。

**姿势 B（判违规，绝不采用）**：为「表达式化循环」另立一套运行期迭代器 / 惰性流 / 新 ABI 求值原语 → 撞 L1-③ 极简 runtime，直接 ❌。

#### A.3.2 双后端发射草图 + 一致性论证

以 `var r: T = for (x in arr) { if (p(x)) { x*2 } else { () } } else { 0 };` 为例（T = i32）。

**C 后端**（已 desugar 后）：
```c
int64_t __r; int64_t __d = 0;
for (int64_t _i = 0; _i < t_slice_len(arr); _i = _i + 1) {
    int64_t x = arr[_i];
    if (p(x)) { __r = x*2; __d = 1; }
}
if (!__d) { __r = 0; }
int64_t r = __r;
```
走 `emit_expr` 的 `"assign"` 分支写回 `__r`。

**LLVM 后端**（同一 desugar AST）：
```llvm
%r = alloca i64; %d = alloca i1; store i1 false, i1* %d
; loop: %x = ..., br %body
; body: %cond = call p(%x); br i1 %cond, label %deliv, label %next
; deliv: store i64 %mul, i64* %r; store i1 true, i1* %d; br label %next
; after-loop: %dd = load i1, %d; br i1 %dd, label %done, label %elseb
; elseb: store i64 0, i64* %r; br label %done
; done: %rv = load i64, %r; store i64 %rv, i64* %r_slot
```

**一致性论证（关键）**：
1. **desugar 在前、分后端在后**：两后端 never 见到「表达式化循环」原始语法，只见到**同一份**归一化的 `var`/`if`/`for`/`assign` AST → lowering 的语义输入完全相同。
2. **「最后一次成功交付」不是 phi**：朴素 phi 只能取「变量终值」，取不到「最后一次非 `unit` 的值」；本姿势用**显式累加器 `__r` + 标志 `__d`** 表达，逻辑在 desugar 阶段定型，两后端只是把这段既有的顺序控制流各译一遍 → 可证明逐字节语义一致。
3. **`else` 必要性在 sema 锁定**：值位置且无 `Never` 出口时，若不能静态证明「必然交付」，则**强制要求 `else`**；这条检查发生在 sema，两后端拿到的已是「要么有 `else` 兜底、要么是 `Never`」的完备 AST，不存在「一边有 else 一边没有」的分叉。
4. **守门**：落 `tools/gate.mjs` 的 `catn_check` + `conformance`（双后端对拍）+ `ir_verify`，专盯 lowering 一致性。

#### A.3.3 依赖标注

| 依赖项 | 现状 | 是否阻塞 |
|---|---|---|
| `match` 表达式 machinery（值 `if` 可同构复用） | ✅ 已实装 | 否 |
| `var` / `if` / `for` 语句 + `"assign"` 节点 + `shadow_check` | ✅ 已实装 | 否（须确保表达式化后仍走这些节点） |
| `unit` / `()` 字面量 | ✅ 已实装 | 否 |
| `@` 转换原语族（补齐的显式出口） | ✅ 已实装 | 否 |
| `Never` / 底类型（跳转原语归 `Never`） | ⚠️ 须形式化落地（本文 P4） | 软阻塞（P4 自身即本提案一部分） |
| **分支/循环 widen-only lub（补齐）类型推导** | ❌ **当前 `match` 要求分支类型一致，无 lub 能力** | **硬阻塞**：P2 须先实现 lub 推导，否则「`i8 + i16 → i16`」「`u8 + i16 → i16`」等示例无法编译期判定 |
| `reference.md` §3.3 文法重写（Statement→Expression 提升） | ❌ 未做 | 软阻塞（spec 同步） |

> **子项目拆分（落地顺序）**：① 先实现 **P2 的 lub 推导**（最小可独立验证，且不依赖表达式化）；② 再做 **P1 表达式化 + P3 循环 `else`**（依赖 ① 与既有 `match`/`var`/`if`/`for`）；③ 最后 **P4 形式化 `Never`**、**P5 移除 `void`**（纯命名/别名，零风险）。①② 任一不过 `catn_check`/`conformance` 则整体退回。

### A.4 开放风险与门禁落点

- **循环动态取值的 lowering 正确性是头号风险**：务必用 §A.3.2 的「累加器 + 标志」姿势，禁止按迭代 phi。门禁：新增 examples（空容器 / 中途 `break` / 末轮交付 / 永不交付 + `else`）双后端对拍。
- **`else` 就近绑定的悬空歧义**：循环体末恰为缺 `else` 的 `if` 时，`else` 归 `if` 而非循环 → 值位置下编译器据此报「缺 `else`」。门禁：嵌套 `if/for` + `else` 的语法歧义用例。
- **spec 大面积重写**：`reference.md` §3.3 须把 If/While/For/Block 从 `Statement` 移到 `Expression` 文法，并保留「语句位置」（`;` 结尾）兼容。门禁：`reference.md` 与 `tc` 实机行为对照测试。
- **哲学层备注**：建议在 `docs/constitution.md` 或 `docs/design.md` 留一条「表达式化是语法统一、不改显式/fail-fast 哲学」的备注，避免后续被误读为世界观变更。
