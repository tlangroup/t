## 0. 结论摘要

**总判定：❌ 不可采纳（整体）。**

来稿约 **65% 的篇幅描述的是 t 语言不存在、且按现行宪法不应存在的机制**（惰性迭代器、生成器协程、async/await/suspend），其闭包记号、类型记号、声明记号、循环记号**均与 t 现行文法不兼容**。

但来稿的**算子分工骨架**（map / filter 分离出专属记号、`|>` 与 delta 体系正交隔离、语法糖六条准入原则）是有价值的，已被吸收进配套草稿。

| 处置 | 数量 | 内容 |
|---|---|---|
| ✅ 吸收 | 3 项 | `\|->` map / `\|>?` filter 记号分工；`\|>` 与 `~>` 共享右侧规则；语法糖六条准入原则 |
| ⚠️ 改造后吸收 | 4 项 | `\|>` 语义重定义；优先级塔落位；词法最大匹配；for-in 联动 |
| ❌ 否决 | 9 项 | `\|it\|` 闭包记号、`feed`/`stop` 生成器、Iterator/Iterable 模型、`\|>>` reduce、终端算子族、`!>` 记号、标识符闭包糖、Delta 体系整体、`Optional`/`List`/`Set` 泛型容器 |
| 🚫 禁止 | 3 项 | `for(A,B)` 笛卡尔积语法、空格敏感的 delta 区段记号、async/await/suspend 全章 |

## 1. 三项 🚫 禁止（触及根本原则，绝对不可为）

### 🚫-1 `for(A, B)` 笛卡尔积语法（来稿 §3.2）

```
for(A,B) ⇒ Cartesian::new(A, || B)
```

`for` 是 t 的**保留关键字**（reference.md §2.3），`for (` 是 `ForStatement` 的确定性 FIRST 集。把 `for(A,B)` 定义成表达式位的适配器构造，使同一 token 序列 `for (` 在同一解析点存在**两条合法解析路径**——直接违反宪法第2条（唯一确定语义）与来稿自设的「歧义零容忍原则」。

另：`Cartesian::new` 用了 `::` 记号，该记号已于 2026-08-01 从 t 移除（reference.md §2.5），且 t 无关联函数/命名空间调用。

**处置**：整节删除。笛卡尔积用嵌套 `for (a in A) { for (b in B) { … } }`，不需要语法。

### 🚫-2 空格敏感的 delta 右侧记号（来稿沿用 design.md §2.6.2 遗留）

```
x ~> +20    // 带符号字面量 ⇒ delta += 20
x ~> + 20   // 运算符区段   ⇒ delta += x + 20
```

**一个空格改变语义**。这同时击穿宪法第2条（唯一确定语义）、第11条（编译器强制唯一格式化——格式化器无法在不改变语义的前提下规范空白）、第10条（AI 稳定生成）。格式化器与语义相互矛盾时，语言不可用。

**处置**：`~>` 右侧统一为**一元函数值**，区段与带符号字面量两种形态全部删除（详见 §3.8）。

### 🚫-3 async / await / suspend 全章（来稿 §九，含 9.1–9.12）

来稿用**整整一章**（约 25% 篇幅）规定同步迭代与协程的隔离规则。t 当前：

- 无 `async` / `await` / `suspend` 关键字（reference.md §2.3 关键字表可查）；
- 无 `Task<T>`、无调度器、无协程栈；
- 宪法第12条只写了「极简协程用于协作式控制流」这一**目标**，无任何生效法律或实现。

为一个不存在的体系撰写「与管道的互斥规则」，等于**凭空为语言增设未经宪法审查的第二运行时**——属宪法第18条 🚫「擅自改未指定设计」范畴。

**处置**：整章删除。配套草稿只保留一句留白：*若未来引入协程，须使用独立记号，不得复用 `|->` / `|>?` / `|>`。*

## 2. 五项致命 ❌（违宪，须先修订）

### ❌-1 `|it| { ... }` 闭包记号（来稿 §1.2、贯穿全文）

来稿全文以 Rust 风格 `|it| expr` 作为闭包字面量。t 的闭包字面量是 **`fn(x: T) Ret { ... }`**（reference.md §3.4 `FuncLit`，M46/M48 已实装、双后端一致、统一 TClosure ABI）。

三重违规：

1. **L-04 等价多写法**：引入 `|it|` 后同一闭包有两种拼法。
2. **真词法歧义**：`|` 是位或运算符。`a |> b |c| d` 无法确定是「管道到闭包 `|c| d`」还是「`b | c | d` 位或链」。来稿的「歧义零容忍原则」在自己的记号上第一条就没守住。
3. **静态类型缺失**：`|it|` 无参数类型标注，依赖上游推断。t 是显式静态类型语言，`FuncLit` 的参数与返回类型均**必写**（L-03）。

**处置**：全部改写为 `fn(x: T) U { ... }`。

### ❌-2 `feed` / `stop` 生成器体系（来稿 §1.3、§二，两章）

来稿把 `feed` 定义为「同步惰性产出迭代序列元素」，脱糖为编译器内部原语 `gen()` / `yield_item()` / `generator_terminate()`。

**这不是薄脱糖，这是新运行时。** 「惰性产出」要求把闭包体切成状态机、保存恢复点与局部变量帧——即无栈协程。来稿自称「所有行为完全等价底层原生原语组合」，但那三个「原生原语」在 t 里**根本不存在**，也不可能由现有 `for`/`while`/闭包组合出来。

违反：

- 宪法第3条（无隐式生命周期——生成器帧的存活期不可静态追溯）；
- 宪法第12条（极简运行时——引入调度状态机）；
- `docs/design.md` §2.6 已裁定的**姿势 A**（贪心展开成 `for` 循环，0 新增 runtime）；姿势 B（惰性流/迭代器对象）当时即被判违规。

**处置**：删除 `feed` / `stop` / `gen` / `yield_item` / `generator_terminate`。等价能力的 t 写法：

| 来稿 feed 用途 | t 合规写法 |
|---|---|
| 一进多出（1→N） | 右侧函数返回 `[]U`，再 `\|> flatten`（std 普通函数） |
| 提前截断 | `\|>?` 过滤，或 std `take(xs, n)` |
| 无限序列 | 不支持（宪法第3条：无隐式生命周期、无无界分配） |

### ❌-3 `Iterator<T>` / `Iterable` 二分模型（来稿 §五，整章）

来稿建立了完整的惰性迭代器模型：生命周期四阶段、单次消耗所有权、`Iterator<Iterator<T>>` 嵌套类型、空迭代默认行为……

t 的现实：

- **无泛型容器类型**。类型系统只有 `[]T` / `[N]T` / `map[K]V` / `Sym32` / `fn(...)Ret`（reference.md §3.5）。`Iterator<T>` / `List<T>` / `Set<T>` / `Optional<T>` 均不可表达。
- **无惰性**。`for (x in xs)` 直接遍历切片底层缓冲。
- **无所有权/借用检查器**。「单次消耗、禁止二次遍历」无从静态判定。

**处置**：整章删除。管道的**唯一载体是 `[]T` 切片**，贪心求值，可重复遍历，无状态。

### ❌-4 `|>` 值管道与函数调用等价（来稿 §1.2）

这是来稿**最隐蔽也最重要**的一处违规，且它同样存在于本项目自己的 `docs/design.md` §2.6。

```
x |> f    ⇔    f(x)
```

两者语义完全相同 → **同一逻辑存在两种标准写法** → 直接违反宪法第2条与 L-04。而 `f(x)` 是不可能删除的（函数调用是语言基石），所以冲突无法靠「删掉另一种」化解。

对比 `|->`：`xs |-> f` 无等价单表达式写法（手写要 `var t: []U = []; for (e in xs) { append(t, f(e)); }`），因此**它挣得了自己的记号**。`|>` 没有。

**处置（配套草稿采用）**：保留 `|>`，但**限定其只能出现在管道链内部**——

- `|>` 的左操作数**必须**自身是管道表达式（`|->` / `|>?` / `|>` 的结果）；否则报错，须写 `f(x)`。
- 反向：一元调用 `f(E)` 若 `E` 是管道表达式，报错，须写 `E |> f`。

这条规则**机械可判定、可由格式化器强制**，使每个语义恰有一种合法拼法，L-04 得以满足。这是本次审查对来稿的实质性修正。

### ❌-5 终端算子族 `collect / take / skip / first / count`（来稿 §七）

```
var top3 = (1..=10) |> take 3;
var arr  = (1..=5) |-> it * 2 |> collect;
```

四重问题：

1. **`take 3` 是并置实参**。t 无并置调用语法，`take 3` 在 t 里不是合法表达式。
2. **`collect` 冗余**。t 管道贪心求值，结果**本来就是** `[]T`，无需收集。
3. **`count` / `first` 冗余**。`slice_len(xs)` 已存在（内建）；首元素是 `xs[0]`。
4. **`(1..=10)` 区间字面量不存在**。`..` 虽在 reference.md §2.5 的标点表里列出，但 lexer 从未实现该 token（`src/lex.tc` 无 `DotDot`），更无 `RangeExpr` 产生式。来稿**每一个示例**都以区间开头，全部无法编译。

**处置**：终端算子全部降级为 `lib/std` 普通函数（`take(xs, n)` / `skip(xs, n)` / `flatten(xss)` / `sum(xs)`），经 `|>` 接入链尾。区间另案（若要 `1..=10`，须单独走 L-15 起草流程，不在管道范围内）。

## 4. Delta 体系专项裁定（❌ 整体缓议）

来稿 §四对 delta 只给了 4 条约束，实质内容仍在本项目 `docs/design.md` §2.6.2 / §2.6.2.1（含用户已确认的 T1–T17 用例）。审查时必须把两者合起来看。

**核心发现：标量 delta 在当前 t 中是冗余语法糖。**

```
x ~> fn(v: i64) i64 { 20 } ~!;     // ≡  x = x + 20;
x ~> f ~> g ~!;                     // ≡  x = x + f(x) + g(x);
```

design.md §2.6.2.1 提出的「跨函数延迟」形态，其自身的 desugar 草图就是：

```
var dx: i64 = 0;
stage_a fn() void { dx = dx + 1; }
commit  fn() void { x = x + dx; dx = 0; }
```

——**普通变量 + 普通赋值**，语言不需要为此提供任何记号。且 §2.6.2.1 自设的「强制设计约束」明确要求 delta 槽必须显式、不得由语言隐藏，这等于承认了「语言不介入」。

那么 delta **唯一非冗余**的场景是什么？是宪法第12条的**沙盒多核并行 ECS**：多个 System 并行对同一 Component 累加，需要语言/编译器保证「顺序无关 + 确定性合并」。手写 `dx += …` 在并行下**无法**保证这一点。

**裁定**：

- ❌ 作为标量语法糖的 `~>` / `~!` / `!>` —— **不采纳**（L-04 冗余）。
- 🚫 空格敏感的区段/带符号字面量二分 —— **禁止**（见 🚫-2）。
- ❌ `!>` 记号 —— **不采纳**（与 design.md 已登记的 `~!` 构成同义双记号，L-04）。
- 📌 **重新提案条件**：待 ECS 并行调度（宪法第12条）有生效法律后，以「System 侧 Component 增量提交原语」重新起草，届时它承载「并行确定性合并」这一不可替代语义，方能通过 L-04。

因此配套草稿 `pipeline.md` **只涵盖管道，不含 delta**。
