## 1. EBNF

```ebnf
// —— 表达式入口下移：赋值的左侧由 OrExpr 改为 PipeExpr ——
// 既有 10 级二元塔（OrExpr … MulExpr）层级与顺序一字不变，本规则只在其外侧包一层。
AssignExpr: PipeExpr ("=" AssignExpr)?

// —— 新增最低二元级 L0，全部左结合 ——
PipeExpr: OrExpr (PipeOp OrExpr)*

PipeOp:
      "|->"                 // PipeMap    元素映射
    | "|>?"                 // PipeFilter 元素过滤
    | "|>"                  // PipeApply  多态管道：标量→直接应用 / 可迭代→逐元素映射（见 §4 / §5.3）
```

- 文法层**允许** `|>` 出现在任意位置；其具体语义由左操作数类型决定（§4 / §5.3），检查期对不合法组合报 `T-PIP-E866` / `T-PIP-E867` 并给出 fix-it。语法宽、语义严，是为了给出精确诊断而非笼统的 parse error。
- 管道算子的右操作数级别为 `OrExpr`，故右侧可写任意非管道表达式：具名函数 `f`、匿名字面量 `fn(v: i32) i32 { … }`、函数类型变量、结构体字段 `h.op`、下标 `fs[i]`。**无「标识符闭包糖」、无 `|v|` 记号**——t 的闭包字面量是 `fn(x: T) U { … }`（reference.md §3.4），右侧只有一条类型规则：*静态类型必须是一元 `FuncType`*。

## 2. 词法

### 2.1 新增记号

```ebnf
OpOrPunct: /* 既有记号 */ | "|->" | "|>?" | "|>"
```

| 字面量 | token 名 | 语义 |
|---|---|---|
| `\|->` | `PipeMap` | 元素映射 |
| `\|>?` | `PipeFilter` | 元素过滤 |
| `\|>`  | `PipeApply` | 链内一元应用 |

### 2.2 最大匹配顺序与破坏性验证

扫描到 `|` 时按长度降序尝试：

```
3 字符：  "|->"  "|>?"
2 字符：  "||"   "|>"
1 字符：  "|"
```

**零破坏证明**（逐一枚举 `|` 后的字符序列在旧文法下的合法性）：

| 新记号 | 旧词法切分 | 旧文法下是否合法 | 结论 |
|---|---|---|---|
| `\|->` | `\|` + `->` | ❌ `->` 只出现在函数返回类型位，`a \| -> b` 从不合法 | 无既有程序受影响 |
| `\|>?` | `\|` + `>` + `?` | ❌ `a \| > ?` 从不合法 | 无既有程序受影响 |
| `\|>`  | `\|` + `>` | ❌ `a \| > b` 从不合法 | 无既有程序受影响 |

因此三个记号的引入**不会改变任何现存合法 t 程序的含义**。注意 `a | -b`（带空格）与 `a|-b` 仍照旧切分为 `|` + `-`，因为其后不是 `>`。

> 对照：来稿提议的 `!>` 记号与一元 `!`、`!=` 相邻，且与已登记的 `~!` 构成同义双记号，已否决（审查 §4）。

### 2.3 与未来体系的记号隔离

若日后引入协程 / 异步流 / ECS delta 提交，**须使用全新记号**，不得复用或重载 `|->` / `|>?` / `|>`（宪法第2条）。

## 3. 优先级与结合性

- 新增**单一最低级 L0**，实现为 `parse_pipe`，包在 `parse_or` 外层；表达式入口由 `parse_or()` 改为 `parse_pipe()`。
- `|->` / `|>?` / `|>` **同级、全部左结合**。
- 既有 10 级塔（`||` > `&&` > `|` > `^` > `&` > `==`/`!=` > 比较 > 移位 > `+`/`-` > `*`/`/`/`%`）**顺序不变**，属 L-03 允许的「塔向下扩展」而非重排。

推论（无需括号即可确定）：

```t
auto a = xs |-> f |>? p;          // ((xs |-> f) |>? p)     左结合
auto b = n + 1 |-> f;             // ((n + 1) |-> f)        管道最松
r = xs |-> f;                     // r = (xs |-> f)         赋值在管道之外
```

> 反之，`xs |-> a + b` 解析为 `xs |-> (a + b)` —— 右侧是一个求值为函数值的表达式，而 `a + b` 不是函数类型，报 `T-PIP-E860`。

## 4. 类型规则

设 `SeqType` 指 `[]T` 或 `[N]T`，元素类型为 `T`。

| 形式 | 左操作数 | 右操作数 | 结果类型 |
|---|---|---|---|
| `E \|-> F` | `SeqType`，元素 `T` | `fn(T) U` | `[]U` |
| `E \|>? F` | `SeqType`，元素 `T` | `fn(T) bool` | `[]T` |
| `E \|> F` | 任意类型 `S` | 类型定向（见下）：`S` 标量 → `fn(S) U` 得 `U`；`S` 为 `Seq[T]` → 若 `F` 形参接受 `S` 整体则 `fn(S) U` 得 `U`（整体应用），否则 `fn(T) U` 得 `[]U`（逐元素映射） |

细则：

1. **右侧元数固定为 1**。非一元报 `T-PIP-E861`（对 `|->` / `|>?` / `|>` 一律适用）。
2. **形参类型匹配**沿用调用点规则：`can_cast(流入类型, 形参0类型)` 为假报 `T-PIP-E862`（与 `check_call_args` 同一判据，保持一致性）。
3. **`|>?` 的谓词返回类型必须严格为 `bool`**，不接受任何可转型的标量（宪法第3条禁止隐式布尔判定），违者报 `T-PIP-E864`。
4. **`|->` / `|>?` 一律产出切片 `[]U` / `[]T`**，即使左侧是 `[N]T`。定长保长度是纯 lowering 优化，**不改变静态类型**，以保持唯一语义。
5. **`|->` / `|>?` 不支持** `map[K]V`、`string`、标量作为左操作数，报 `T-PIP-E863`（二者为显式集合算子，左操作数必须可迭代）。`|>` 不受此限：标量左操作数走直接应用、可迭代左操作数走映射（§5.3）。map 遍历用既有 `for (k, v in m)`。
6. **`|>` 类型定向解析顺序**（左操作数 `E`，类型 `S`；右侧 `F`，形参 `P`）：
   - ① 若 `can_cast(S, P)`（整体应用成立）→ `E |> F` ⇔ `F(E)`，结果 `U`；
   - ② 否则若 `S` 为 `Seq[T]` 且 `can_cast(T, P)` → 逐元素映射，结果 `[]U`；
   - ③ 否则报 `T-PIP-E867`（`F` 与 `E` 无任何匹配形态）。
   - 优先级：① 先于 ②；当两者同时满足（罕见，如 `F: fn(any) any` 且 `E` 可迭代）时取①整体应用，并可发 `T-PIP-E866` 提示（非错误）。
7. 空序列输入产出空序列，无诊断、无特例。
8. `paren`（`( … )`）为透传节点，判定类型与「是否管道表达式」时须先剥壳。

## 5. 规范语义

### 5.1 求值即贪心（姿势 A）

管道**不引入惰性**。整条链在其所在语句处**完整求值**，产出一个真实的 `[]T` 缓冲。结果可重复遍历、无消耗状态、无生命周期约束——与任何普通切片完全同质。

### 5.2 融合是规范语义，而非优化

**权威定义**：一条由连续元素级算子（`|->` / `|>?`）构成的链，其语义为——

> 按下标 `0 .. slice_len(src)-1` **升序**遍历源序列；对每个元素，**按链上书写顺序**依次施加各级算子；`|>?` 谓词为假则立即跳过该元素的后续所有级；末级产出的值 `append` 到结果序列。

即「逐元素纵向穿过整条链」，而非「逐级横向物化中间数组」。这是**唯一**的规范语义，不存在「等价的另一种展开」。

> 为何必须写死：对纯函数两种展开结果相同，但对**带副作用**的阶段函数（如打印、写全局计数器）调用顺序不同。宪法第7条（确定性可复现）要求语义唯一，故规范定为融合序。

### 5.3 多态分派规则（`|>` 的语义由左操作数类型决定）

`|>` 不再受「必须续链」限制；它的语义由左操作数 `E` 的类型在**检查期**确定：

1. **`E` 为标量 / 非可迭代类型 `S`** → **直接应用**：`E |> F` ⇔ `F(E)`，要求 `F: fn(S) U`，结果类型 `U`。
   - 例：`PI |> sin` ⇔ `sin(PI)`；`auto y = 3 |> add1;` ⇔ `add1(3)`。
2. **`E` 为可迭代类型 `Seq[T]`（`[]T` / `[N]T`）** → **类型定向二选一**：
   - ① 若 `F` 的形参类型 `P` 满足 `can_cast(Seq[T], P)`（即 `F` 接受**整个序列**）→ **整体应用** `F(E)`，结果 `U`；
   - ② 否则若 `can_cast(T, P)`（即 `F` 接受**单个元素**）→ **逐元素映射**，结果 `[]U`；
   - ③ 否则报 `T-PIP-E867`（`F` 与 `E` 无任何匹配形态）。
   - 优先级：① 先于 ②。当两者同时满足（如 `F: fn(any) any` 且 `E` 可迭代）时取①整体应用，避免歧义（可发 `T-PIP-E866` 提示）。

> 为何这样定：使「链尾聚合」与「逐元素映射」共存于同一 `|>`——`xs |> hp_of`（`hp_of: fn(Enemy)i32` 不接受 `[]Enemy`）走②映射；`xs |> sum_i32`（`sum_i32: fn([]i32)i32` 接受整个切片）走①整体应用。无额外记号。

> **L-04 和解**：`x |> f ⇔ f(x)`（标量情形）看似制造等价多写法，但它属于**语法糖有唯一展开**（`x |> f` 唯一脱糖为 `f(x)`），不触发解析期双路径，与 L-04 的「唯一确定语义 / 解析无歧义」不冲突。这是用户裁定的有意设计选择，记录在 §13 A。

`|->` 与 `|>?` 仍是**显式**算子（左操作数必须可迭代，否则 `T-PIP-E863`），`|>` 是对应它们的「多态 / 自动」版本。三者分工：

```t
auto a = xs |> hp_of;                 // ✅ 多态：可迭代 → 映射 → []i32
auto b = PI |> sin;                   // ✅ 多态：标量 → 应用 → sin(PI)
auto c = xs |>? is_alive |> hp_of;    // ✅ 过滤 + 映射（|> 在可迭代上走映射）
auto d = xs |>? is_alive |> hp_of |> sum_i32;  // ✅ 末段 |> 整体应用 sum_i32（fn([]i32)i32）
auto e = 3 |> hp_of;                  // ❌ E867：hp_of: fn(Enemy)i32 既不能接受 i32 也不能映射 i32
```

### 5.4 右侧函数只求值一次

管道右操作数在**进入循环之前**求值，自左向右，各求值一次。因此 `xs |-> make_adder(k)` 只调用一次 `make_adder`，其返回的闭包在整个循环中复用；`xs |-> fn(v: i32) i32 { … }` 只构造一次闭包环境。

## 6. 脱糖（唯一确定）

### 6.1 命名约定

脱糖引入的合成绑定使用全局递增计数器，前缀固定，与既有 `__lam_N` / `__env_N` 同族：

| 前缀 | 用途 |
|---|---|
| `__pf<N>` | 右侧函数值的一次性求值槽 |
| `__ps<N>` | 结果序列 |
| `__pe<N>` | 循环元素变量 |

### 6.2 提升位置

整个脱糖块被提升到**当前语句之前**，原管道表达式就地替换为最终结果的引用。提升不跨语句边界、不跨块。

### 6.3 展开示例

**（a）单级映射**

```t
auto ys = xs |-> hp_of;
```

```t
var __pf0: fn(Enemy) i32 = hp_of;
var __ps1: []i32 = [];
for (__pe2 in xs) {
    append(__ps1, __pf0(__pe2));
}
auto ys = __ps1;
```

**（b）过滤 + 映射 + 链尾聚合（融合为单循环、单次分配）**

```t
auto total = es |>? is_alive |-> hp_of |> sum_i32;
```

```t
var __pf0: fn(Enemy) bool = is_alive;
var __pf1: fn(Enemy) i32  = hp_of;
var __ps2: []i32 = [];
for (__pe3 in es) {
    if (__pf0(__pe3)) {
        append(__ps2, __pf1(__pe3));
    }
}
auto total = sum_i32(__ps2);
```

**（c）`|>` 切段**：`|>` 之后若再出现元素级算子，链被切成两段，每段各自融合为一个循环。

```t
auto r = xs |-> f |> flatten |-> g;
```

```t
var __pf0: fn(i64) []i64 = f;
var __ps1: [][]i64 = [];
for (__pe2 in xs) { append(__ps1, __pf0(__pe2)); }
var __t3: []i64 = flatten(__ps1);
var __pf4: fn(i64) i64 = g;
var __ps5: []i64 = [];
for (__pe6 in __t3) { append(__ps5, __pf4(__pe6)); }
auto r = __ps5;
```

### 6.4 后端零改动

脱糖产物只含既有节点种类（`var_decl` / `for_each` / `if` / `call` / `assignment`），因此 **C 与 LLVM 两个后端无需任何新增发射分支**。这是姿势 A 的直接红利，也自动继承双后端一致性。

> ⚠ 实现铁律：合成的循环体必须是**语句链表头**（`list_push(-1, -1, stmt)`），不可直接塞 `parse_block()` 产出的 block 节点，否则 `desugar_lambdas` 会越界（参考 `parse.tc` 的 agent spawn 脱糖）。

## 7. 上下文限制（分配可追溯）

`|->` / `|>?` 需要提升语句块，故**只允许**出现在下列四类位置（剥 paren 后判定）：

1. `var` / `const` / `auto` 声明的初始化器；
2. 赋值语句右侧 `Lhs = Pipeline;`；
3. `return Pipeline;`；
4. 表达式语句 `Pipeline;`。

其余位置一律报 `T-PIP-E865`，fix-it 为「先绑定到局部变量」。明确禁止：

| 禁用位置 | 理由 |
|---|---|
| `if` / `while` / `for` 条件 | 条件位无提升点 |
| `&&` / `\|\|` 右操作数 | 提升会破坏短路求值 |
| `match` 臂体、`when` 守卫 | 臂是条件执行，提升会改变求值时机 |
| 函数调用实参 | 提升会改变实参间的副作用顺序 |
| 数组下标、结构体字面量字段值 | 同上 |

**副作用**：这条限制使每一次「新序列的分配」都必然对应一个**具名绑定或显式 return**，满足宪法第3条「无隐式内存分配、可静态追溯」。

> `|>` 本身不产生循环（脱糖为普通调用），但因 R1 它只能续在元素级算子之后，故整条链共享同一限制。

| `T-PIP-E865` | `T_PIPE_BAD_CONTEXT` | error | 管道出现在禁用上下文（§7） |
| `T-PIP-E866` | `T_PIPE_DISPATCH_AMBIG` | warning | `\|>` 整体应用与逐元素映射同时满足（罕见，如 `fn(any)any`），已按规则取整体应用 |
| `T-PIP-E867` | `T_PIPE_NO_MATCH` | error | `\|>` 的 `F` 与左操作数 `E` 无任何匹配形态（既不可整体应用、也不可逐元素映射） |
| `T-PIP-W868` | `W_PIPE_RESULT_UNUSED` | warning | 表达式语句位的管道结果被丢弃 |
| 869–879 | — | — | 预留 |

诊断消息须**指名道姓**（同 `T_MATCH_NONEXHAUSTIVE` 的先例）：报出实际类型、期望类型，以及可直接套用的 fix-it 写法。

## 9. 与既有体系的关系

| 体系 | 关系 |
|---|---|
| `for (x in xs)` | 脱糖目标，**不修改**其文法与语义 |
| `FuncLit` / `FuncType` / 闭包（M46/M48） | 右操作数的唯一来源；统一 TClosure ABI，具名函数与闭包可互换 |
| `append` / `slice_len` 内建 | 脱糖使用，无新增内建（**不触发「新增内建须六处齐全」铁律**） |
| 泛型 `comptime T: any` | 管道脱糖是内联的，类型在展开点已具体化，**不依赖泛型**；不受「泛型体内嵌套泛型调用不单态化」的已知限制影响 |
| `match` / `when` | 正交；但管道禁止出现在臂内（§7） |
| agent / ECS | 主要受益场景：`components \|>? active \|-> step \|> commit_all` |
| 模块 / `import` | 右侧函数跨模块时须 `export`；⚠ 跨模块调用必须 `import` 被调方，否则链接期 undefined |
| Delta / 协程 | 无交互（均未采纳 / 不存在） |

### 9.1 配套 std（`lib/std/seq.tc`，另案起草）

管道**不内置**任何终端算子。以下为普通 `export` 函数，经 `|>` 接入链尾：

```t
flatten fn(comptime T: any, xss: [][]T) []T
take    fn(comptime T: any, xs: []T, n: u64) []T
skip    fn(comptime T: any, xs: []T, n: u64) []T
```

> ⚠ 三者签名带 `comptime T`，而 `|>` 右侧要求一元函数值 —— 单态化后的 `flatten` 仍是二元（含 comptime 参数的降级形态）。**这是本草稿最大的一处实现风险**，须在实装前验证单态化产物能否作为一元函数值绑定；若不能，`flatten` 等只能以 `flatten(T, xss)` 普通调用形式使用，链须在此处断开。已列入 §12 待裁定项。

## 10. 示例（均须可编译，实装时逐个进 `examples/`）

```t
Enemy struct {
    hp: i32,
    speed: i32,
}

is_alive fn(e: Enemy) bool {
    return e.hp > 0;
}

hp_of fn(e: Enemy) i32 {
    return e.hp;
}

sum_i32 fn(xs: []i32) i32 {
    var acc: i32 = 0;
    for (v in xs) {
        acc = acc + v;
    }
    return acc;
}

// 单级映射
all_hp fn(es: []Enemy) []i32 {
    return es |-> hp_of;
}

// 过滤 + 映射 + 聚合（单循环、单次分配）
alive_hp_total fn(es: []Enemy) i32 {
    return es |>? is_alive |-> hp_of |> sum_i32;
}

// 匿名闭包 + 按值捕获外层参数
scaled fn(xs: []i32, k: i32) []i32 {
    return xs |-> fn(v: i32) i32 { return v * k; };
}

// 匿名谓词
positives fn(xs: []i64) []i64 {
    return xs |>? fn(v: i64) bool { return v > 0; };
}
```

**反例（各对应一条诊断）**

```t
auto n = xs |> sum_i32;                 // ✅ 现合法：sum_i32: fn([]i32)i32 接受整个切片 → 整体应用
auto m = sum_i32(es |-> hp_of);         // ✅ 现合法：链尾 |> sum_i32 与 es |-> hp_of |> sum_i32 等价
auto e = 3 |> hp_of;                    // T-PIP-E867  左侧标量 i32，hp_of: fn(Enemy)i32 无任何匹配形态
auto y = 3 |-> hp_of;                   // T-PIP-E863  |-> 左侧必须可迭代（显式 map，标量报错）
auto z = es |-> 42;                     // T-PIP-E860  右侧非函数值
auto w = es |>? hp_of;                  // T-PIP-E864  谓词返回 i32 而非 bool
if ((es |>? is_alive) != null) { }      // T-PIP-E865  条件位禁用
```
