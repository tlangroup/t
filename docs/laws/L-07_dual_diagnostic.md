# t 语言法律 · 双格式诊断法

> **法律编号：L-07** ｜ 名称：双格式诊断法 ｜ 制定依据：《t 语言设计宪法》第一章第6条（双格式结构化诊断输出原则）
> **状态：草案（待宪法审查）**
> 本法为细则法，将宪法第6条「双格式结构化诊断输出」落实为可检查的代码约束：所有编译诊断须同时输出人类可读文本与 JSON 结构化报文，支撑 Agent 闭环迭代。

---

## 第一章 适用范围

- **第1条 适用对象** — 编译器 `src/tc.tc` 的诊断发射路径、所有 error / warning 产出点、诊断渲染器。
- **第2条 不适用** — 运行期日志 / 断言信息不强制双格式，但鼓励同源。

---

## 第二章 正文条款

- **第3条 双格式输出** — 每一条编译诊断须同时产出：①人类可读文本（含消息、位置、建议）；② JSON 结构化报文（机器可解析）。
- **第4条 JSON 报文结构** — 报文至少含：规则编号、文件、行、列、严重度（error/warning）、消息、建议修复。字段稳定、向后兼容。
- **第5条 同源一致** — 两种格式须由同一诊断数据渲染，不得出现文本与 JSON 描述冲突。
- **第6条 全诊断覆盖** — 所有 error / warning 路径均须具备双格式能力，不得存在仅单格式的诊断。

---

## 第三章 与宪法关系

- **第7条 宪法映射** — 本法对应宪法第6条（双格式结构化诊断输出）；是第10条（AI 友好可导出 AST）的诊断侧支撑。

---

## 第四章 合规判据

| 条款 | 合规判据 | 当前实现状态 |
|---|---|---|
| 第3条 双格式输出 | 每条诊断同时产文本 + JSON | ⚠️（仅 `print_json` 落地，缺人类可读文本渲染器） |
| 第4条 JSON 结构 | 报文含规则编号/位置/严重度/建议 | ⚠️（JSON 已有，结构待补全建议字段） |
| 第5条 同源一致 | 文本与 JSON 同源于一诊断对象 | ⚠️（文本半边缺失，无法验证一致） |
| 第6条 全诊断覆盖 | 无仅单格式诊断 | ⚠️（依赖文本渲染器补全后验证） |
