# t 语言法律 · 静态类型前提法

> **法律编号：L-03** ｜ 名称：静态类型前提法 ｜ 制定依据：《t 语言设计宪法》第一章第1条（静态类型前提原则）
> **状态：草案（待宪法审查）**
> 本法为细则法，将宪法第1条「静态类型前提」落实为可检查的代码约束，规定语言所有行为与约束须建立在编译期类型安全、无运行时类型歧义之上。

---

## 第一章 适用范围

- **第1条 适用对象** — 编译器 `src/tc.tc` 的类型推断与检查阶段、类型系统定义、被编译的 t 程序类型声明、示例 `examples/*.tc`。
- **第2条 不适用** — 运行期数值运算的溢出语义由《零未定义行为法》(L-09) 另行规定；隐式转换禁令由《全行为显式可追溯法》(L-02) 规定。

---

## 第二章 正文条款

- **第3条 类型静态已知** — 所有变量、字段、参数、返回值的类型须在编译期确定；无运行时类型歧义、无动态类型推断导致的多解。
- **第4条 固定位宽标量** — 数值标量须使用固定位宽类型（`i8/i16/i32/i64`、`u8/u16/u32/u64`、`f32/f64` 等），不得使用依赖平台宽度的 `int` / `long` / `size_t` 等模糊类型。
- **第5条 显式转换** — 跨位宽、跨符号、整浮之间的转换须使用显式转换内建（如 `int_to_*` / `uint_to_*` / 构造器），不得自动插入。
- **第6条 泛型与类型参数** — 泛型 / 类型参数须有可解析的约束，其实例化在编译期完成，无运行期类型特化。
- **第7条 无运行时类型查询** — 不得存在 `typeof` / 运行期类型分支等破坏静态可预判的行为。

---

## 第三章 与宪法关系

- **第8条 宪法映射** — 本法对应宪法第1条（静态类型前提），是全部铁律的前提性基础；争议裁决以宪法为准。

---

## 第四章 合规判据

| 条款 | 合规判据 | 当前实现状态 |
|---|---|---|
| 第3条 类型静态已知 | checker 全程静态推断（`infer_expr`），无运行期类型推导 | ✅ |
| 第4条 固定位宽 | 类型表为固定位宽集合，无平台依赖模糊类型 | ✅ |
| 第5条 显式转换 | 跨类型操作若无显式转换节点即报错；`T_TYPE_IMPLICIT_CAST` 仅显式触发 | ✅ |
| 第6条 泛型约束 | 泛型参数编译期可解析（如 `@derive` 表驱） | ✅（部分 trait 仍手写） |
| 第7条 无运行时查询 | 全仓无运行期类型分支 | ✅ |
