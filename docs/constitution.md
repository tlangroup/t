# t 语言设计宪法

> 本宪法为 t 语言设计的根本规范。所有语言特性、编译器实现、工具链决策均须遵循;与本章冲突者,以本章为准。

## 序言(宪法目标)

本宪法的目标是设计一门语言,其根本目标为:

> **数据第一 · ECS 架构强适配 · 智能体第一 · 引擎底层 · AI 稳定生成 · AI Agent 友好 · 静态类型 · 人类编程友好**

第一章所列 13 条顶层铁律,均为达成上述目标而设的不可突破约束;任何语言设计取舍,以是否推进此八目标为最高裁决标准。(注:「智能体第一」于 2026-08-03 由用户直接指令增补,属宪法修正案,待依第23条走四层评审正式确认。)

**宪法的主要用途** — 除确立语言目标与顶层铁律外,本宪法的**主要用途是审查法律**:对作为下层规范的法律文件(具体语言开发指导),在其制定与修改时提供**四层评审意见**(✅ 合规 / ⚠️ 警示 / ❌ 违宪 / 🚫 禁止),并据以裁决法律可否生效;法律生效后,用于检查代码执行是否合规。

**目标阐释**
- **数据第一** — 数据是程序的主角:结构体、枚举、Flag 位域、注解、外部数据表导入均为一等公民,业务逻辑弱依附于数据定义;CSV/JSON 在编译期导入并固化为静态常量,最大限度消除硬编码分支。
- **ECS 架构强适配** — 原生契合 Entity-Component-System:组件即纯数据(结构体 / Flag 位域),系统弱耦合于数据布局;支持 AOS/SOA 内存排布以优化缓存命中,Component 字段可用定长 / 紧凑类型与字符串驻留符号(Sym),使海量实体批处理高效且可预测。
- **智能体第一** — Agent 是语言的一等公民:由「身份(atom,复用 M50) + 显式状态(纯数据 struct) + 能力集(类型化工具 fn) + 消息回路」构成,其定义与行为完全由静态类型数据与普通函数表达,不引入隐式堆 / GC / 运行时类型歧义(呼应第1/3/8条);Agent 既可独立运行,也可作为 ECS 的 System 编排实体世界,使「数据第一」「ECS 第一」「智能体第一」三者统一于同一套静态数据模型。设计纲要见 `docs/agent_first.md`(草案)。
- **引擎底层** — 贴近硬件、性能可预测:固定位宽标量、显式内存与生命周期、无 GC 隐式开销;内存布局可控,契合物理仿真与嵌入式等底层场景。
- **AI 稳定生成** — 同一逻辑只有一种标准写法,无语法变体、无等价多写,杜绝模型风格漂移与随机不一致;产出确定、可复现、可审查。
- **AI Agent 友好** — 编译错误同时输出人类可读文本与 JSON 结构化诊断,支持 AST 导出与编译期类型全自省,使 Agent 能闭环「解析报错→自动改码→重新编译」并自主迭代。(注:本项指语言**可被** Agent 消费;「智能体第一」指 Agent **作为语言一等公民被编写**,二者正交、互补。)
- **静态类型** — 编译期类型安全、无运行时类型歧义;固定位宽、显式转换,所有行为静态可预判。

- **人类编程友好** — 语言须对人类开发者友好,具体分三层十二维:认知层(可读性优先语法、局部可推理、最小惊喜、一致性)、错误层(人类可读错误、错误可恢复、结构化错误人体工学 `?`)、工作流层(快速反馈/REPL、调试可见、平缓学习曲线、工具与文档文化、命名与模块清晰)。本目标首项已落地裁决为**局部类型推断**:声明分三关键字——`var`(变量,可变)、`const`(静态常量,编译期可知、不可变)、`let`(动态常量,运行期绑定一次后不可变);三者局部声明类型标注均可选,由初始化器经静态分析推断(推断结果仍为固定位宽具体类型,守「静态类型」支柱);类型标注语义定为「可选约束/覆盖」而非替代声明,以守第2条唯一写法;整数字面量默认 `i32`,仅上下文需更宽时拓宽;推断回填类型节点后局部默认可被闭包捕获;顶层 fn 签名、全局 `var`/`const`/`let`、struct 字段仍须标注(稳定性/分离编译/AI 契约)。既有 `auto x = e;` 推断形式保留为 `let` 的同义别名并标记弃用。【宪法审查:✅ 合规 — 与第2/3/8条一致;标注定为可选约束,消解与唯一写法之张力】

## 第一章 顶层铁律(不可突破)

### 基础语义层
- **第1条 静态类型前提原则** — 静态类型是全部铁律的前提:语言所有行为与约束均建立在编译期类型安全、无运行时类型歧义之上。
- **第2条 唯一确定语义原则(语义层)** — 同一逻辑仅一种标准写法,语义确定无歧义;同输入同行为、无实现定义行为,杜绝多等价写法导致的生成不一致。
- **第3条 全行为显式可追溯原则** — 所有行为显式、无隐式,且可静态追溯;无隐式类型转换、无隐式内存分配、无隐式布尔判定、无隐式生命周期。
- **第4条 AST 原生结构化元编程原则** — 元编程全部基于 AST 编译期自省,彻底废弃字符串拼接宏;可读、可调试、可自动修复。
- **第5条 数据一等公民驱动架构原则** — 结构体、枚举、Flag 位域、注解、外部数据表导入为一等公民,业务逻辑弱依附于数据定义。
- **第6条 双格式结构化诊断输出原则** — 所有编译诊断双输出:人类可读文本 + 机器结构化报文(JSON)。

### 工程与底层可靠性层
- **第7条 确定性可复现编译原则(构建层)** — 同源码跨环境/跨时间产出逐字节一致的构建产物(字节级可复现)。
- **第8条 零未定义行为强安全约束原则** — 杜绝未定义行为;危险操作须显式标注且可静态审查。
- **第9条 ABI 与版本契约稳定原则** — 公开 ABI 与语言版本间保持向后兼容契约。

### AI 与自动化迭代层
- **第10条 AI 友好可导出 AST 原则** — 编译器可导出标准化、可序列化的 AST 与稳定诊断接口,供 AI 批量分析/重构/迭代;语法固定无风格变体由第2条保证。
- **第11条 编译器强制唯一格式化规范原则** — 编译器强制唯一代码格式,消除风格分歧,降低生成漂移。

### 运行时与引擎架构层
- **第12条 极简协程并发 + 沙盒多核并行 + 资源显式绑定原则** — 极简协程用于协作式控制流;沙盒多核并行用于 ECS 数据并行,须顺序无关以保持确定性(呼应第7条);资源显式绑定、无隐式 GC。

### 元规则
- **第13条 铁律校验(元规则)** — 任何新增特性 / 语法 / 注解,必须通过全部铁律校验,否则不得进入语言。

## 第三章 法律与宪法审查

- **第15条 法律的地位** — 法律是宪法之下、指导具体语言开发的根本规范,以「法律文件」形式存在(如 `docs/` 下的开发指导文档)。法律不得与宪法任何条款冲突;冲突时以宪法为准。现行活动设计文档(`reference.md`、`design.md`、`bootstrap.md` 等)将逐步重构为法律文件。

- **第16条 法律的制定与执行** — 具体的语言开发指导(类型系统、运行时契约、工具链约定等)应编写为法律文件。法律之下设**语法规则子层**:以规范 EBNF 书写、经法律验证(L-15 语法规则法指定的 L-04 / L-02 / L-03 / L-14 等)、并入 `docs/reference.md` 为语法权威载体,其起草工作流(草稿 → 生效 → 并入 → 失效)由 L-15 规定。法律用于**检查代码执行**:对照宪法铁律与法律条文,检验编译器、运行时与工具链实现是否合规。

- **第17条 宪法审查目的** — 宪法的主要用途是**审查法律**。任何法律的制定、修改、废除,均须提交宪法审查,取得评审意见后方可生效。

- **第18条 四层评审意见** — 法律修改时,宪法提供四层评审意见:
  - ✅ **合规** — 与宪法一致或属澄清性补充,可直接纳入;
  - ⚠️ **警示** — 与宪法存在轻微张力,须说明理由并经用户确认;
  - ❌ **违宪** — 与宪法条款冲突,须先修订或废除冲突条款方可生效;
  - 🚫 **禁止** — 触及根本原则(如未经审查令法律生效、绕过评审、擅自改未指定设计文件),绝对不可为。

- **第19条 法律生效** — 法律经宪法审查取得 ✅ 或经确认的 ⚠️ 意见后,方可生效执行;取得 ❌ / 🚫 者须先行修订。

## 第四章 协作管理施行

- **第20条 默认工作模式** — 非平凡任务先出分步计划与取舍,经用户确认后再执行;简单、明确、单一动作的任务可直接处理。

- **第21条 沟通风格** — 简洁直接,结论先行;仅在风险点、架构选择、方案分歧处展开说明。默认中文。

- **第22条 红线** — ①有歧义先问不猜;②不擅自改未指定设计文件(设计文件指 `docs/` 目录下所有 `.md` 文件)。

- **第23条 宪法自身修正** — 对本宪法的任何修改,亦须依第18条四层评审意见评审;🚫 禁止项(如擅自令宪法生效、绕过评审)绝对不可为。

- **第24条 生效** — 本宪法由用户明确下令(如"生效")后生效;此前仅为草稿,不具约束力。
