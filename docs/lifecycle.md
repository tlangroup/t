# t 语言 · 显式生命周期管理设计（权威梳理）

> 本文是 **t 语言显式生命周期模型** 的权威梳理文档（design note，非新特性提案）。
> 范围：仅整理**已落地**的机制与其合规依据，**不改语言**。新机制（所有权 / RAII / 析构）属后续里程碑，见 §8。
> 来源条款：`docs/constitution.md` 第3/12条、`docs/laws/L-02_explicit.md`、`docs/laws/L-13_coroutine_parallel.md`、`docs/reference.md`、`docs/bootstrap.md`、`docs/syntax/drafts/fid.md`。
> 配套文档：`docs/reference.md` §3.3（语句/defer）、§3.8（Sym）、§3.9（fid）、`docs/bootstrap.md`（arena）。

## 1. 定位与宪法/法律来源

t 语言是**静态类型、数据驱动、ECS 取向**的语言，定位「引擎底层」——性能可预测、内存布局可控、无 GC 隐式开销。生命周期管理因此被宪法与法律**显式约束**，而非交给运行时自动回收。

| 来源 | 条文 | 对生命周期的约束 |
|---|---|---|
| 宪法 第3条 | 全行为显式可追溯 | 无隐式类型转换 / 内存分配 / 布尔判定 / **生命周期** |
| 宪法 第12条 | 协程并行资源绑定 | 资源**显式绑定**、无隐式 GC；生命周期静态可追踪 |
| L-02 第5条 | 无隐式内存分配 | 栈 / 堆（`*_new`）/ arena 对象须**显式区分**，不得隐藏分配 |
| L-02 第6条 | 无隐式生命周期 | 无 GC、无自动回收；释放经显式 `free` / `arena_reset` / 作用域退出 |
| L-13 第6条 | 资源显式绑定 | 内存 / 文件句柄 / GPU 等资源显式绑定与释放，生命周期静态可追踪 |
| L-09 | 零 UB | 资源误用（重复释放 / 悬空访问）走**确定性中止** `t_panic`，而非 UB |

**总原则（三句话）：**
1. **没有 GC，没有自动回收。** 任何资源都由「分配者」显式释放。
2. **分配点即文档。** 栈 / 堆 / arena 在源码里形态可辨，不存在「背后悄悄 malloc」的语句。
3. **误用即中止，不沉默。** 重复 `fclose`、访问已关闭句柄等走 `t_panic`，绝不产生未定义行为。

## 2. 生命周期机制全景

| 机制 | 分类 | 分配 | 释放 | 作用域语义 | 落地状态 |
|---|---|---|---|---|---|
| 局部 `var`/`const`/`auto` | 栈 / 值类型 | 声明即存在 | 作用域退出即失效（值类型无堆资源） | 块级 | ✅ |
| 堆对象 `*_new` / `t_alloc` | 堆 | `t_*_new` / `t_alloc` | 显式 `free` | 手动 | ✅（运行时集中，无散落 malloc） |
| Arena `t_arena_*` | 区域 | `t_arena_alloc` | `t_arena_free_all` / `arena_reset` 整池 | 区域级 | ✅（编译器自身即 arena 模型） |
| `defer { ... }` | 延迟释放钩子 | — | **函数退出**时 LIFO 执行 | **函数级**（非块级） | ✅ 已实装（L-15 采用） |
| `sym_release` / `sym_release_all` | 区域（符号驻留池） | 自动 intern | 整池释放 | 区域级 | ✅ tote |
| `fid` 文件句柄 | 句柄 | `fopen` | 显式 `fclose`（不幂等） | 手动，**无自动关闭** | ✅ tote（M51–M53） |
| 闭包 `TClosure` / 环境 | 堆 | `t_alloc` | **当前不回收（有意泄漏）** | 手动（未实现） | ⚠️ v1 限制 |
| 管道 `|>` | 值（无状态） | 整链完整求值 | 产出真实 `[]T` 缓冲，可重复遍历 | 语句级 | ✅（无生命周期约束） |

## 3. 各机制详述

### 3.1 栈 / 值类型（局部绑定）
- `var x: T`、`const x: T = ...`、`auto x = 初始化器` 声明局部；`auto` 类型由初始化器推断且**禁止显式标注**（见 `reference.md` §3.3）。
- 值类型（标量、定长数组、struct 值）生命周期随作用域：块退出即失效。
- 若局部持有堆/句柄资源，作用域退出**不会**自动回收该资源——须配合 §3.4 / §3.5 显式释放。

### 3.2 堆对象（`*_new` + `free`）
- 堆分配统一经 `t_*_new` / `t_alloc` 系列内建；运行时不得散落裸 `malloc`（L-02 第5条合规判据 ⚠️ 个别路径待审）。
- 释放须经显式 `free`。**无引用计数、无所有权推导**——谁分配、谁负责释放是编码契约。
- 典型形态：动态容器（`t_map_new`/`t_map_put`）、闭包环境（见 §3.7）等。

### 3.3 Arena（区域分配）
- 接口：`t_arena_new()` / `t_arena_alloc(a, size)` / `t_arena_free_all(a)`（`bootstrap.md` L75–82）。
- 语义：**一次性批处理**——分配多次，区域结束 `t_arena_free_all` 一次性回收。
- 编译器自身即 arena 模型：「编译结束统一释放」，**完全回避 GC 与所有权系统**，是把自举提前数月的关键取舍。
- 适用：生存期彼此重叠、统一时刻到期的对象批（如一次请求的临时缓冲）。

### 3.4 `defer { ... }`（函数级延迟释放）
- 文法：`DeferStatement: "defer" Block`（`reference.md` L1046）。**必须接块**，裸 `defer fclose(f);` 是语法错误。
- 语义：登记到**当前函数**延迟栈，于 `return` / 函数尾按 **LIFO** 执行；写在 `if`/`while` 块内**仍到函数退出才触发**（**非块级作用域退出**）。
- 捕获：延迟块捕获的是**退出时**的变量状态（引用语义），非定义时快照。
- 适用：**句柄生命周期 == 函数生命周期**的情形（打开→全程使用→退出关闭）。
- ⚠️ 反模式：「打开→写→读回校验」等**块内须落盘**的场景不能靠 `defer`，必须显式 `fclose`（`reference.md` D6 L1638）。`defer` 与显式 `fclose` **不可并用**（`fclose` 不幂等，重复关闭 panic）。

### 3.5 `sym_release` / `sym_release_all`（符号驻留池）
- 字符串驻留（interning）按 `tag` 分池；`Sym = "str"` 赋值时编译器自动插入 `sym_intern`（`reference.md` §3.8）。
- `sym_release("<tag>")`：释放该 tag 对应**整池**（区域结束语义），之后同 tag 的 intern 可重新使用。
- `sym_release_all()`：遍历全局 `Symbols` 注册表释放所有剩余池。
- 适用：批量符号（如词法分析后的标识符表）在某一阶段结束时整体回收。

### 3.6 `fid` 文件句柄（无自动关闭）
- 分配 `fopen(path, :mode)`；失败返回无效句柄，用 `fid_is_open(f)` 显式探测（**无隐式异常/重试**）。
- 释放 `fclose(f)`：**不幂等**，重复关闭 → `t_panic`；关闭 stdin/stdout/stderr → panic。
- **无自动关闭**：句柄不随作用域回收，须显式 `fclose`（`reference.md` D6 L1637）。
- 容量硬上限 `T_FID_MAX = 256`；`0/1/2` 恒为 stdin/stdout/stderr，用户同时最多 **253** 个；表满 `fopen` 返回 -1（与打开失败同一表象，靠 `fid_is_open` 区分）。
- 长生命周期批量打开须自行 `fclose` 回收，无 GC。

### 3.7 闭包 `TClosure` / 环境（v1 限制）
- 闭包脱糖为「堆分配环境结构 `__env_N` + 堆分配 `TClosure{fn, env}`」（`reference.md` L1222–1225）。
- **v1 生命周期**：环境与 `TClosure` 用 `t_alloc` 堆分配且**不回收（有意泄漏）**。自动释放需引入所有权或 GC，属后续里程碑。
- 捕获为**按值语义**：构造那一刻拷贝自由变量，之后外层改动不回灌、闭包内改动不外泄。

### 3.8 管道 `|>` （无状态值）
- 管道**不引入惰性**：整条链在所在语句处完整求值，产出真实 `[]T` 缓冲（`reference.md` L2358）。
- 产出可重复遍历、无消耗状态、**无生命周期约束**，与普通切片同质。
- 含义：管道不产生「跨语句持有」的资源，不参与生命周期管理。

## 5. 编码推荐模式（最佳实践）

1. **谁分配，谁释放**：堆对象 / 句柄的释放点应与分配点在同一函数内可静态追踪。
2. **句柄活到函数尾 → 用 `defer`**：`defer { fclose(f); }` 比手动 `fclose` 更不易漏。
3. **块内须落盘 → 显式 `fclose`**：`defer` 是函数级，写/读回环中途要落盘必须显式关，不能依赖 `defer`。
4. **批量临时对象 → 用 arena / `sym_release`**：同生同灭的对象用区域释放，避免逐个 `free`。
5. **不要重复释放**：`fclose` 不幂等，释放后不得再引用；`defer` 与显式 `fclose` 不可并用。
6. **闭包在 v1 会泄漏**：长生命周期服务中避免高频构造闭包，或自行在合适时机回收（当前无自动机制）。
7. **探测而非假设**：`fopen` 后一律 `fid_is_open` 判断；句柄表满与打开失败表象相同。

## 6. 已知限制与技术债

- **闭包 / 环境先泄漏**：v1 有意不回收，自动释放依赖所有权或 GC（后续里程碑）。`reference.md` L1225。
- **`defer` 仅函数级**：块级作用域退出不触发，块内落盘须手写 `fclose`（`reference.md` D6）。
- **L-02 第5条个别路径待审**：运行时是否存在散落分配路径未全数确认。
- **L-02 第8条规则编号维度待补**：诊断已有行/列，但缺「违反规则编号」维度，定位成本偏高。
- **Array↔Slice 缺 lowering**：`[N]T` → `[]T` 无转换 lowering，`can_cast` 当前对数组/切片无条件放行，传定长数组给 `[]T` 形参可能静默读垃圾长度（编译器侧 P0 技术债，用户侧表现为段错误）。

---

## 7. 与确定性 / 零 UB 的关系

- 所有释放路径都是**显式、可静态追踪**的，契合 L-08（确定性可复现编译）与 L-09（零 UB）。
- 资源误用（重复释放、悬空访问、关闭标准流）一律 `t_panic` 中止，绝不退化为未定义行为——这是「无隐式生命周期」的安全兜底。

## 8. 开放问题与后续里程碑（Stage 3 预告）

> `docs/bootstrap.md` 明确：「规范的通用内存管理设计推迟到 Stage 3 之后。」以下为待设计方向，**本文不展开、不落地**：

- **所有权 / RAII / 析构**：是否需要引入显式所有权标注或 `drop`/析构钩子，以替代「闭包泄漏」与手写 `free`。
- **块级 `defer`**：是否新增块级作用域退出触发（当前仅函数级），以支援块内落盘场景。
- **引用 / 指针存活范围标注**：在 L-02 第6条「显式界定」基础上，是否需要语法级生命周期标注（ borrow 检查雏形）。
- **句柄自动回收策略**：在保持「无隐式 GC」前提下，是否允许 arena 化绑定的句柄（句柄池随区域释放）。

任何上述方向的落地，须经对应法律（L-02 / L-13 / L-09）审查与 `tools/gate.mjs` 门禁回归，并更新本文。
