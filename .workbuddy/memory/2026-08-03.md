## Atom 升级为「全局符号」：编译期 intern + 静态全局名表（本次）
- 用户裁定：atom 是**全局 symbol**（对标 `examples/sym_global.tc` 的 `Sym32`/`Sym16`），但形态选**编译期 intern + 静态全局名表**，而非复用 `Sym` 的运行时池 —— `:ok` 仍是零开销 i64，额外获得 `atom_str(a) -> string` 反查名字。
- 机制：编译器把 intern 表发射为**外部链接全局**，运行时 `t_atom_str` 经 `extern` 引用之。
  - C 后端：`TStr t_atom_table[] = { TSTR_LIT(""), TSTR_LIT("ok"), ... };` + `int64_t t_atom_count = N;`
  - LLVM 后端：`@t_atom_table = global [N x %TStr] [ %TStr { ptr @.sK, i64 L }, ... ]` + `@t_atom_count = global i64 N`
  - index 0 是占位空串（`atom_intern` 返回 1-based），故 `t_atom_table[id]` 直接命中；`id<=0 || id>=count` 返回空串。
  - **无 atom 的模块也必须发射最小表**（只含占位），否则运行时的 extern 引用链接不上。
- 新增改动点：`emit_c_atom_table`（`emit_unit` 内调用）、`emit_ll_atom_table`（`emit_llunit` 内 `emit_llglobals` 之后调用）；`atom_str` 四处内建派发（check `ti_mk("String")` / td `td_mk("string")` / C `t_atom_str(x)` / LLVM `@tll_atom_str(i64, ptr)` out 指针）+ `llph` declare；runtime `t_atom_str` + shim `tll_atom_str`。
- 验证：`examples/atom.tc` 扩充 `atom_str` 段（含变量、函数返回值、`k as atom` 遍历名表、越界空串），**双后端逐行一致**；新增 `examples/atom.expected.txt` 让 run_examples 真正覆盖它（此前 atom.tc 没有 expected 文件 = 完全没测，18/18）；新增 conformance `pass/p23_atom_ok.tc` + `fail/f33_atom_type_mismatch.tc`（57/57）。
- 结果：gate **L2 13/13 全绿**（178s），四代不动点 IR md5 `5cb6fbb4…`，`out/dbg/tc.exe` + `out/rls/tc.exe` 已安装；IR 基线重录为 25 targets / 75 entries。

### 致命坑：运行时 extern 编译器发射的全局 → 自举鸡生蛋
- 现象：`undefined symbol: t_atom_table`。因为**引导编译器**（改动前的 `tc.exe`）不含「发射原子表」的代码，它编出的 `tc.exe` 生成物里没有该全局，而新 runtime 又引用它。
- 通法（三步逃生阀）：
  1. `clang -c -DT_ATOM_BOOTSTRAP_STUB ... runtime/t_runtime.c` 手工编一版桩运行时（`t_atom_str` 直接返空串，不引用外部符号）→ `llvm-ar rcs` 打包，绕开 `tools/build_runtime.mjs`。
  2. 用**旧** `tc.exe` + 桩运行时编出含发射逻辑的中间代编译器。
  3. 去掉宏重建真运行时，用中间代编译器编最终编译器 → 生成物自带表 → 链接通过；再跑到不动点。
  - 宏 `T_ATOM_BOOTSTRAP_STUB` 已作为常驻逃生阀保留在 `runtime/t_runtime.c`（带注释说明），日常构建不定义。
- **反例教训**：曾试图用「已含发射逻辑但 IR 有 bug」的中间代去编下一代 —— 中间代编译器发射什么，取决于**它自己的二进制**，改 src 不影响。发现中间代产物非法必须退回上一代重编，不能原地打转。
- **LLVM 数组常量元素必须内联结构常量**：`[N x %TStr] [ @.ts0 ]` 非法（`@.tsN` 是 ptr）。要写 `%TStr { ptr @.sN, i64 LEN }`。`ll_strlit` 调用后可从 `ll_last_sref` / `ll_last_slen` 取到这两项。

## 既有 bug（与 atom 无关，未修）
- `i64(bool)` 强转在**原编译器**就返回 0（如 `i64(true)`→0、`i64(1==1)`→0）。属 `bool→i64` 转换缺陷。atom demo 已绕开（用 if/match 展示相等性，不依赖该强转）。如需修，定位 checker `infer_expr` 的 cast 分支与 `ll_cast_v`/`emit_expr` 的 i1→i64 路径。

## 踩坑提醒
- match 的 arm body **只能是单表达式**（如 `0 => "zero"`），不能是 `{ }` 块。用了块体才会 `parse error: unexpected token in expression: {`。
- `build --output X` 会在 X 后补 `.exe`；若 X 已存在同名目录会冲突（"cannot open output file ... is a directory"）。重建规范编译器须 `--output <临时名>` 再 `cp`。
- `print`/`println` 只接受 `string`；打印 i64 走 `StringBuilder`（`sb_new`/`sb_append_i64`/`sb_to_str`）或 `int_to_str`。

## M51：fid 文件描述符 + `<` 序列化操作符（实装完成，草稿待采纳）

- 需求：新增 `fid` 标量类型；全局 `stdin`/`stdout`/`stderr`；`<` 作序列化操作符；格式由「打开方式 × 后缀」经**注册表**解析（text 默认 text、`.json`→json；binary 默认 rawbin、`.pb`→protobuf）。
- 草稿 `docs/syntax/drafts/fid.md`（L-15 流程，**未采纳**，未并入 reference.md）。
- 结果：conformance **65/65**，run_examples **19/19** 双后端一致，gate **L2 13/13 全绿（71s）**，不动点 IR md5 `f4a88e1d…`；dbg/rls 两档编译器 IR 逐字节相同。

### 设计要点
- `fid` 完全复刻 `atom` 的标量管线（`scalar_pred`/`scalar_bits`/`scalar_ctype`，64 位，LLVM `i64`/C `int64_t`）。
- `stdin`/`stdout`/`stderr` 在 `parse_primary` 的 Identifier 分支拦截 → `fidconst` 节点（0/1/2）；声明位置由 `sym_define` 顶部的保留名守卫拦（`T_FID_RESERVED_NAME`）。
- `<` 的二义由**左操作数静态类型**消解：`fid` ⇒ 脱糖成 `serialize` 节点；否则仍是小于比较。`fid` 无序，`>`/`<=`/`>=` 报 `T_FID_NOT_ORDERED`（`>` 预留给未来反序列化）。
- `serialize` 结果类型 = 目标 fid ⇒ `f < a < b` 靠左结合天然落成嵌套调用，无临时量、无额外规则。
- **mode/kind/fmt 在发射期编译成整数码**（mode 0..5 / kind 0..1 / fmt 0..3），运行时**不读 atom 名表** —— 这是刻意规避 M50 那类「运行时 extern 编译器发射的全局」自举鸡生蛋。
- 格式在 `fopen` 时按 (类别, 后缀) 查表一次性解析并**冻结进句柄记录**，不在每次写出时重算。
- 诊断码分两轴：mode 轴 `T_FID_MODE_NOT_LITERAL`/`T_FID_BAD_MODE`，format 轴 `T_FID_FORMAT_NOT_LITERAL`/`T_FID_BAD_FORMAT`；另有 `T_FID_UNSERIALIZABLE`。

### 新坑（值得记住）
- **`fid_format(f) -> atom` 的 atom 必须在检查期 intern**：LLVM 后端 `@t_atom_table` 在函数体**之前**发射，发射期才 `atom_intern` 会导致 id ≥ `t_atom_count`，`atom_str` 还原成空串。修法：在 `check` 阶段（与 atom 字面量同期）调 `fid_intern_fmt_atoms()`。
- **内建调用的实参不走 `infer_expr` 的通用遍历**：嵌套在 `atom_str(fid_format(x))` 里的内建不会被 walk 到。凡「见到某内建就要做副作用」的逻辑，别挂在实参遍历上。
- **`defer` 是函数级不是块级**，且 `DeferStatement: "defer" Block` —— `defer fclose(f);` 是**语法错误**，须 `defer { fclose(f); }`；写在 `if` 块里的 defer 仍在函数退出才触发。「块内写完读回校验」必须显式 `fclose`。⚠️ `docs/reference.md` L907 写的「作用域退出时按 LIFO 执行」描述不精确，待用户裁定是否订正。
- **exe 的 md5 不能用来判自举不动点**：`-gcodeview` 把 `--output` 的名字写进调试信息，`tc_g5.exe` 与 `tc_g6.exe` 必然不同。gate 比的是 `emit-ll` 出来的 `.ll` md5，手工验证也必须比 `.ll`。
- **json 是纯值编码器，没有「原样输出」旁路**：`j < "["` 得到字符串值 `"["` 而非数组开括号。v1 拼不出 JSON 文档结构，留给 v2 聚合序列化。给旁路等于让同一个 `<` 有两种字节语义（违反 L-04）。
- C 后端 `fid_format` 发射一度拼错（多包了不存在的 `t_fmt_atom`、实参括号位置错）—— `run --emit-c` 走的不是完整 C 链路，**必须靠 run_examples 的 C 后端实跑**才暴露。

### §7.1 `>` 消歧锚点修正（用户裁定）
- 原稿写「消歧看右操作数是否为类型名」（还造了 `T_FID_READ_AMBIGUOUS` 伪问题），与 D1 不自洽。用户裁定：消歧锚点应与 `<` 一致 = **左操作数静态类型**。`fid` 无序 ⇒ `fid > x` 绝不可能是大于比较，只能是反序列化；非 fid 在左才是大于比较。
- 新规则表：左=fid + `<`→写(右是值)；左=fid + `>`→读(右是**类型**)；左=fid + `==`/`!=`→比较(D1)；左=fid + `<=`/`>=`→仍 `T_FID_NOT_ORDERED`；左≠fid + `>`→大于比较。
- 副作用：`f > 3`（右是值非类型）→ 报 `T_FID_DESERIALIZE_NEEDS_TYPE`，不再退化成大于比较；彻底消除类型名/值名歧义。
- 同步改了草案：§7.1 消歧段、兜底 `fread` 说明（改「显式内建」非「歧义兜底」）、§5 L-04 读路径行、§6 `>` 条目（不再预留报错）。并加注「采纳 §7.1 须同步修订 D1 的 `>` 预留报错项为反序列化」。

### 实现要点
- **解析层（关键坑）**：`string` / `StringBuilder` / `void` / `map` 是**关键字**（`KwString` 等，src/tc.tc:4337 附近注册），不是 ident ⇒ `f > string` 里的 `string` 走不到 `parse_primary` 的 ident 分支，直接落进「unexpected token in expression」。修法：新增 `tok_type_only(t)` 判定「只可能是类型的关键字」，在 `parse_cmp`（约 6914）见到 `op == ">"` 且下一 token 是类型专用关键字时，右操作数改走 `parse_type()` 而非 `parse_shift()`。

## M54 补充：`{N}` 位置索引不支持，且当前**静默误解析**（用户提问触发的探针）

- 用户问「format 支持 `{1}` 这样的语法吗」。答：**不支持**。Python 那套分两层——外层**替换字段语法**（`{0}`/`{1}`/`{name}` 选第几个参数）+ 内层**格式规范迷你语言**（`>10.2f` 描述排版）。M54 只实现了内层；外层因 `t` 无变参、无 `Any`、字符串无 `+`/无插值，做不了。
- **实测行为（探针跑过，`sb_append_fmt_int(b, spec, 42)`）**：

  | spec | 输出 | 实际解析 |
  |---|---|---|
  | `"{1}"` | `42` | 剥 `{}` → `1` → **width=1**（对 42 无可见效果，纯巧合） |
  | `"{0}"` | `42` | width=0 |
  | `"{}"` | `42` | 空 spec |
  | `"{0:>10}"` | `        42` | 剥 `{}` 后取**最后一个 `:` 之后** → `>10` 生效，索引被丢弃 ✅ |
  | `"{1} {0}"` | `42` | 剥首尾成 `1} {0` → width=1 + type=`}`，**余下字符静默丢弃** |
  | `"name"` | `42` | type=`n`，`ame` 静默丢弃 |

- **根因**：`fmt_parse`（t_runtime.c:203）的剥壳只做「去首尾 `{}` + 取最后一个 `:` 之后」，剩余部分**逐字段贪心解析、不校验是否吃完**，尾部残留一律忽略 ⇒ 任何非法 spec 都不报错。
- **`{0:>10}` 能work是"自动兼容多种写法"的副产品**（目的是让人直接粘贴 Python 文档的 spec），不是真支持字段索引。
