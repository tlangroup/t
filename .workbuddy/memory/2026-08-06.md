## M-meta Phase B（CTFE 求值器）✅ 落地 — gate L2 13/0/0

**核心决策：`meta_pass()` 挂在 checker 之前**（`run_check` 内 `mark_call_callees()` 之后、`check_decl` 之前）。
设计文档原写"checker 之后新增 eval_meta"，实测**之前**更优：折叠后是普通字面量节点，
检查器/双后端/单态化**全部零改动**，直接消掉了"第二解释层漂移"风险的大半。

**第二决策：求值结果用字面量节点 id 表示，不引入 `MetaValue` 结构体。**
`int`/`bool`/`string` 节点即值载体。好处：① 折叠 = 把字面量内容拷进 `comptime` 节点自身
（改 kind/sa/ia/ba，清 na..nd/la），无需重接父指针；② 规避 Win64 聚合按值传参 ABI 坑。

**模块组成**（`src/tc.tc`，`run_check fn` 之前）：
- 环境：`g_menv_name[]`/`g_menv_val[]` 平栈 + `g_menv_base`(帧基)/`g_menv_nglobal`(全局常量区)。
  `menv_find` 只看**当前帧 + 全局区**，调用方局部刻意不可见（meta fn 是纯函数，不做动态作用域）。
- `meta_eval` / `meta_eval_unary` / `meta_eval_binary`(含 `&&`/`||` 惰性短路) / `meta_eval_call` /
  `meta_eval_builtin` / `meta_exec`(0=seq 1=return 2=break 3=continue) / `meta_do_assign` /
  `meta_fold_expr` / `meta_run_block`(执行后置 `la=-1`) / `meta_walk*` / `meta_pass`。
- 泛型模板本体用 `g_meta_quiet = func_is_generic(d)` 静默跳过，只在实例化副本上求值。

**⚠ 编译期 `print` 必须写 stderr，不能写 stdout。**
stdout 是机器可读通道（check 的 JSON、emit-ll 的 IR），且 `tools/conformance.mjs` 对 stdout
做跨编译器**逐字节归一化对拍**（`normalize()` + `r0.stdout !== r.stdout`）。污染 stdout 会炸 conformance。

→ **`@compile_log`/`@compile_warn` 因此从 Phase D 计划中删除**（已被覆盖，且不引入新符号）。

## M-meta Phase C：值参数单态化 ✅（gate L2 13/0/0）

`instantiate_generic` 的单态化键从「只有类型」扩到「类型 + 值」。形参按**声明类型**分流
（`meta_param_is_type`）：`type`/`any`/无标注 → 类型参数；整数族/`bool`/`string` → 值参数。可混用。

**新增 6 个 helper（都放在 `instantiate_generic` 之前）**：
`meta_param_is_type` / `meta_subst_val_kids` / `meta_subst_val_node`（改写 `ident{sa==name}` 表达式节点）/
`meta_val_key`（键编码）/ `meta_eval_value_arg`（CTFE 求值 + 类型 + 范围校验）/
`rewrite_generic_callsite`（调用点改写，抽出来给两条路径共用）。

**关键设计抉择：值参数直接把字面量节点代入实例体**，而不是在实例开头插 `meta const N = ...`。
理由：`[N]i64` 的数组长度槽在 `resolve_ti` 里**要求 int 字面量节点**，常量名满足不了。
实测 `sum_sq(5)` → `alloca [5 x i64]` ✅。

**键编码**（`meta_val_key`）：int → 十进制（负数前缀 `n`，`-5`→`n5`）；bool → `true`/`false`；
string → `"s"+len+"_"+前12个可读字符(非字母数字→下划线)+"_"+FNV-1a(32)`。
**哈希不能省** —— 字符清洗会让 `"a-b"` 与 `"a_b"` 撞名。实测 `repeat("ab-c",2)` → `repeat__s4_ab_c_3217929650_2`。

**诊断顺序踩坑**：`meta X: f64` 一开始报 `T_META_NOT_CONST`（求值器先拒浮点，指向实参）。
把**声明类型检查提到 `meta_eval` 之前**才报 `T_META_VALUE_PARAM_TYPE`（指向形参）。
诊断要指向真正的病灶，不是最先崩的那一层。

## M-meta Phase D：编译期内建 ✅（gate L2 13/0/0，本会话续完收尾）

六个内建全部落地：`@compile_error`/`@type_equal`/`@type_size`/`@type_name`/`@zeroed`/`@str_from_bytes` + `sym_intern`（无 `@`）；`Sym` 一级化（bw=32/alen=32）。

**分流（两类 `@` 内建）**：
- *类型查询* `@type_name`/`@type_size`/`@type_equal`/`@zeroed` → 纯折叠为字面量/`array_lit`，运行期位置也合法（检查器照常对其做类型检查，零 IR 漂移）。
- *CTFE-only* `@str_from_bytes`/`@compile_error` → 只在编译期求值/折叠；运行期上下文（非 `meta` 块、非 `meta` 形参 `meta fn`）调用一律 `T_META_RUNTIME_CTX`。

**⚠ `meta T: type` 类型绑定透传（本阶段关键修复）**：初版 `meta get_width(u32)` 因把类型实参当值 `meta_eval` → 报 `T_META_READ_RUNTIME`。
修法：CTFE 环境加并行槽 `g_menv_ty`（与 `g_menv_val` 同槽，存「该绑定是类型还是值」；`-1`=值绑定，≥0=类型节点 id）；
`meta_eval_call` 对类型形参走 `meta_type_arg_node` 取实参类型节点（**别对其 `meta_eval` 当值**）；
`mb_bound_type` 把 `named{T}` 沿 `menv` 类型绑定解析（循环 ≤16）→ `@type_equal(T,u32)`/`@type_size(T)` 能看到被单态化绑定的具体类型。

**⚠ CTFE 数组值须深拷贝**：`meta_eval_array_lit`/`meta_eval_index`/`meta_do_assign`（下标赋值就地改 `Child.val`）；
`meta_val_copy` 在变量绑定/`meta_do_assign`/`meta_eval_call` **三处**深拷贝 —— t 数组是值类型，`b=a;b[0]=9` 若不拷贝会污染源 `a`（实测误返 909 而非 709）。

**`@zeroed`**：`mb_zero_value` 按类型递归构造零值（标量→0/`false`/`""`；定长数组递归填 0，上限 65536；TypeAliasDecl 递归展开）→ 折成 `array_lit`。

**`@str_from_bytes`/`sym_intern`**：CTFE 经 `meta_bytes_to_str` 由 `[N]u8`+长度构造 string/Sym（`Sym="str"` 自动驻留）。

**⚠ `Sym` 一级化须放在查过用户自定义 Sym 之后**：`resolve_ti` + `resolve_type_desc` 兜底返回 `Sym`（bw=32/alen=32）**仅当程序未自带 `Sym` 时生效** —— 否则自举的 `tc.tc`（自带 `Sym struct`）会拿错类型描述，LLVM 端 `var sym: Sym` 直接 IR 崩。这是自举安全红线。

**分支剪枝**：`mb_prune_if` 剪掉未取分支里的 `@compile_error`，不误报；被取分支触发 `T_META_COMPILE_ERROR`（Zig 语义）。

**诊断码**：新增 T_META_RUNTIME_CTX / T_META_UNKNOWN_TYPE / T_META_TYPE_AS_VALUE / T_META_UNKNOWN_BUILTIN；T_META_COMPILE_ERROR 复用。
