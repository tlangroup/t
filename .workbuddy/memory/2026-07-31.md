## M30 map 字面量 + for-in 迭代 ✅

延续 M29（map 内建端到端），补齐 map 的两块使用体验，并顺手修掉一个静默正确性 bug。

### 交付
- **map 字面量**：`var m: map[K]V = [k1: v1, k2: v2];`。解析层（`parse_map_lit`）早已存在，本次补 emit 路径。
  - `is_map_lit(e)` 助手；C 后端 `emit_stmt` 的 var_decl 分支、LLVM `ll_local_decl` 各加一段。

  - **`var m: map[K]V;` 无初始化时也建空表**（此前是未初始化指针），声明即可用，不必再 `m = map_new(m)`。
- **for-in 迭代键**：`for (k in m) { … }`，按插入序，绑定变量类型 = K。
  - runtime 已有 `t_map_count`/`t_map_key_str_at`/`t_map_key_int_at`，只需 3 个 `tll_*` shim（str 版走 TStr 出参）。
  - `check_stmt` 的 for_each 加 Map 分支（et = key）；`collect_local_types` 加 `cat=="map"` → `fs_set(key)`。
  - C/LLVM 双后端 for_each 各加 map 分支；`emit_lldeclares` 加 3 条 declare。
- **map 字面量类型推断**：整型键/值统一提升 i64（复刻 array_lit 规则），否则 `["a": 1]` 推成 `map[string]u8` 与声明失配。

### 修掉的静默 bug：窄整型键
`map[i32]i64` 此前 `map_get` 恒返回 0（len 正常、迭代正常，只有查不中）。根因：runtime 按 `int64_t*` 读键，而后端直接对 i32 变量取址 → 高 4 字节是栈垃圾，put 与 get 时不同。
修法：**整型键一律按 int64 落盘**。
- C：`&(int64_t){(int64_t)(<expr>)}`（C99 复合字面量是左值）。
- LLVM：新增 `ll_map_keyptr(kn, keytd)`，非聚合键一律 `ll_map_argptr(kn, td_named_mk("scalar","i64"))`，内部会先 `ll_cast_v` 扩宽。
- 附带收益：**键与值都可以直接写字面量了**（`map_set(m, "k", 11)` / `map_get(m, 8)`），此前受 C 后端取址限制必须先存局部变量。值侧同样用复合字面量 `&(V){(V)(expr)}`（仅标量；聚合仍取原表达式地址，C 不允许 cast 到 struct）。
- 新增 `call_arg_node(cid, ix)` 助手：C 后端 map 分派需要实参**节点**（不只是已发射的字符串）来反查类型。

## Sym 新类型设计讨论（纯咨询，未写文档/未落代码）
用户提议为 ECS Component 字符串需求新增 `Sym` 类型：Component 字段存 u16/u32 整数 id，字符串内容在 intern 池；赋值时自动 intern 或复用已有 id；编码人员主动释放。
本轮确认三项决策：
1. **声明语法** `Sym32("NPCName") name = "我是NPC";` —— 池 tag 是**类型的一部分**（编译期字面量），`Sym32("A") ≠ Sym32("B")` 且禁止跨池赋值（编译器强制，防 id 串池）。
2. **释放为按池批量**：编码人员确认所有相关 Component 已释放后，一次性释放整个池（region 生命周期，无 refcount、无 per-sym 释放）。需 per-pool 释放函数 + 可选全局全释放。
3. **Component 必须定长**：不能有变长字段；Sym 字段本身是固定 u32/u16，满足定长。"必须指定长度"含义待澄清（池内字符串最大字节长度=定长槽？还是仅"Component 只能固定宽"）。
实现建议：每 tag 生成一个编译期全局池对象 `g_sympool_<tag>`，intern/release 经该全局（免运行期池查找）；复用 map builtin 的 `t_`/`tll_` 双后端 + runtime 模式；parser 需支持 `Sym32("tag"[, len])` 类型描述，`desc_to_c` 落 `uint32_t`/`uint16_t`，`ti_equal` 按 tag 字符串判等。
状态：纯咨询，未落代码/文档。
**澄清（用户 22:03）**："指定长度"≠字符串定长槽，也≠仅定宽替代。**字符串在池内是不定长的**；`Sym32("xxx")` 在 Component 里**仅是一个 32 位 ID（u32 固定宽）**。"Component 必须定长"= Component 字段只能是定宽类型，不能嵌变长 string/slice；变长字符串整体住在池外（region 管理），故 Component 结构仍是定宽 POD，合规。因此**不需要任何长度参数**，语法就是 `Sym32("xxx")` / `Sym16("xxx")`。
池实现：每 tag 一个独立池 = 变长字节 bump 分配器（各自 malloc 的 growable buffer，bulk release 时真能回收）+ hash 表(string→id 去重) + entries 数组(id→ptr 供 sym_str 反查)；无 per-entry 释放、无 refcount、无 free-list，整池释放即 free buffer+hash。id 0=空；Sym16 上限 65535 超界报错不 wrap。
**决策（用户 22:12）**：确认加轻量 `Symbols` 注册表。编译期自动在 `t__ginit()` 注册各池指针（tag→&g_sympool_<tag>），仅供 init / teardown / debug（sym_release_all、dump、未来动态 sym_pool_get），**绝不进入 intern / per-pool 释放热路径**（热路径直打 `g_sympool_<tag>`，零额外开销）。id 仍每池自增、不打通成统一空间。
