## M32 map 索引写 m[k] = v ✅

补齐 map 写对称能力：`m[k]=v` 编译为 `t_map_put`/`tll_map_put`（find-or-insert）。**关键坑**：`a=b` 是 `"assign"` 节点（`emit_expr`/`emit_lle` 分支），不是 `"assignment"`（`emit_stmt`/`emit_llstmt` 分支，几乎死代码）——误改后者导致改动全不生效，长时间误判为 stale 二进制。双后端均支持单层/嵌套（嵌套 C 用 `(*(TMap**)t_map_val_ptr(base,&k))` 求 TMap*）。
验证：定点 9c68f878 / difftest 27/27 / conformance 29/29 / 两阶段自举 IR 逐字节相同 / `examples/map_assign.{tc,expected.txt}` C==LLVM。
注：「空 map 声明崩溃」是误报——实际是旧的读-存回退路径（键未命中写零缓冲）崩溃；改用 `t_map_put` 后消失。`print(scalar)` 在 LLVM 后端仍崩（**已于 M34 修复**，见下）。

## M30 map 字面量 + for-in 迭代 ✅

延续 M29（map 内建端到端），补齐 map 的两块使用体验，并顺手修掉一个静默正确性 bug。

### 交付
- **map 字面量**：`var m: map[K]V = [k1: v1, k2: v2];`。解析层（`parse_map_lit`）早已存在，本次补 emit 路径。
  - `is_map_lit(e)` 助手；C 后端 `emit_stmt` 的 var_decl 分支、LLVM `ll_local_decl` 各加一段。
  - 与切片字面量同范式：`t_map_new`/`tll_map_new` + 逐项 `put`。
  - **`var m: map[K]V;` 无初始化时也建空表**（此前是未初始化指针），声明即可用，不必再 `m = map_new(m)`。
- **for-in 迭代键**：`for (k in m) { … }`，按插入序，绑定变量类型 = K。
  - runtime 已有 `t_map_count`/`t_map_key_str_at`/`t_map_key_int_at`，只需 3 个 `tll_*` shim（str 版走 TStr 出参）。
  - `check_stmt` 的 for_each 加 Map 分支（et = key）；`collect_local_types` 加 `cat=="map"` → `fs_set(key)`。
  - C/LLVM 双后端 for_each 各加 map 分支；`emit_lldeclares` 加 3 条 declare。
- **map 字面量类型推断**：整型键/值统一提升 i64（复刻 array_lit 规则），否则 `["a": 1]` 推成 `map[string]u8` 与声明失配。

### 修掉的静默 bug：窄整型键
`map[i32]i64` 此前 `map_get` 恒返回 0（len 正常、迭代正常，只有查不中）。根因：runtime 按 `int64_t*` 读键，而后端直接对 i32 变量取址 → 高 4 字节是栈垃圾，put 与 get 时不同。
修法：**整型键一律按 int64 落盘**。
- C：`&(int64_t){(int64_t)(<expr>)}`（C99 复合字面量是左值）。
- LLVM：新增 `ll_map_keyptr(kn, keytd)`，非聚合键一律 `ll_map_argptr(kn, td_named_mk("scalar","i64"))`，内部会先 `ll_cast_v` 扩宽。
- 附带收益：**键与值都可以直接写字面量了**（`map_set(m, "k", 11)` / `map_get(m, 8)`），此前受 C 后端取址限制必须先存局部变量。值侧同样用复合字面量 `&(V){(V)(expr)}`（仅标量；聚合仍取原表达式地址，C 不允许 cast 到 struct）。
- 新增 `call_arg_node(cid, ix)` 助手：C 后端 map 分派需要实参**节点**（不只是已发射的字符串）来反查类型。

### 新发现（独立既有 bug，未修）：`cat2`..`cat6` 未接入运行时
- 现象：用户程序调用 `cat2(a, b)` 时 C 后端报 `call to undeclared function 'cat2'`，LLVM 后端 .ll 引用未定义 `@cat2` → 链接失败。
- 根因：`cat2`..`cat6` 仅在**编译器自身源码**内定义（src/tote.tc L997-1031），既无 builtin 发射分支（对比 `int_to_str` 在 L9926/L13056 有处理），runtime（t_runtime.c/.h）与 t_shim_ll.c 也无 `t_catN`/`tll_catN`。即用户态字符串拼接 `cat2..cat6` 当前**完全不可用**。
- 影响：凡需字符串拼接的用户程序都得绕道 `StringBuilder`（`sb_append_str`/`sb_append_char`）。文档"一律 cat2..cat6"与实际不符。
- 修复方向（未做）：runtime 加 `t_cat2..t_cat6`（TStr 拼接）+ `tll_cat2..` shim；`emit_expr`(C)/`emit_lle`(LLVM)/类型推断 三处加 `catN` builtin 分支。属独立任务，未纳入本次范围，待用户确认再修。

## M34：修复 `print(scalar)` LLVM 后端崩溃 ✅
`print(x)`（x 为 i64 等标量）此前能通过类型检查，到 LLVM 后端生成 `call void @tll_print(ptr %t0)` 而 `%t0` 是 `i64`，触发 IR 校验失败 `'i64' but expected 'ptr'` → `clang link failed`。C 后端同理会发 `t_print(<i64>)` 触发 C 类型错。根因：类型检查对**内建调用实参类型完全不校验**（`builtin_ret` 只返回返回类型）。
- **修复**：在 `infer_expr` 的 `call` 分支（L7052 的 map_get 特判之后），对 `print`/`println`/`eprint` 的实参加 `String` 约束——非 `String`（且非 `Unknown`）即发 `T_TYPE_MISMATCH`（清晰中文报错 + 位置 + 提示用 `int_to_str`/`to_string`/`cat*`）。
  - 注意 `infer_expr` 形参 `e` 才是 i64 节点索引，`n` 是 `Node` 结构；初版误用 `n_file(n)` 导致编译器自身重编译时 `@t.n_file(i64 %v.n)` 报 ptr 错，改为 `e` 后正常。
  - 该检查在 `run_check()` 阶段触发，`has_errors()` 立即中止，根本不会进入 `emit_llunit`，故彻底消除后端崩溃。
- **回归用例**：`tests/conformance/fail/f12_print_scalar.tc`（`// EXPECT: error T_TYPE_MISMATCH`，含 `print(n)` + `println(7)`）。所有现有示例的 `print(` 均传字符串/`int_to_str(...)`/`cat*`，无误伤。
- **验证**：定点（两阶段自举 IR 逐字节相同 `a75de97a…`）/ difftest 27/27 / conformance **30/30**（含 f12）/ shadow_check + catn_check 均 OK / UNSUPPORTED 0。canonical 提升 `build/tote/tote.exe`（= tote-c，与 tote-b IR 一致）。
