# 2026-08-05 工作日志

## 选项①收尾：修 path_exists + toml 自动定位工程根（src/tc.tc）

### 根因（OOM）
- `compute_src_roots` 旧 walk 在循环体内调用 `path_resolve(mod_dir_of(cur))`。
  `path_resolve` 走 `_fullpath`；走到盘符根 `C:` 时 `_fullpath("C:")` 把「C 盘当前目录」展开成
  `C:/Users/seesaw`，于是 `C:/` ↔ `C:/Users/seesaw` 来回震荡，`parent==cur` 永不触发，
  每次 `path_resolve`+`sb_cat` 都从 arena 分配 → `arena: out of memory`。
- 叠加：仓库根 `t/tote.toml` 存在，walk 一路爬到仓库根把 `t/src` 加进候选源码根，import 解析空间被污染。
- 旧版还埋了 `sb_cat3(cur,"/tote.toml")` 只有 2 实参（catn 静态检查才抓出；LLVM 后端不支持 sb_cat2..6）。

### 修法（已落地并验证）
- 新增纯字符串 `parent_dir_of`（剥尾斜杠、找最后 `/`或`\`，盘符根/无分隔符返回 ""），循环内**完全不碰 `path_resolve`/`_fullpath`**，杜绝震荡。
- `compute_src_roots`：入口目录仅一次 `path_resolve` 兜底；向上遍历用 `parent_dir_of`，硬上限 `guard<32`。
- 拼接改走 `StringBuilder`（`sb_new`/`sb_append_str`/`sb_to_str`），不用 `sb_cat2`。
- `path_exists` 维持调 `file_exists` 内建（上一轮已改，根除绝对路径下 sys_run 外shell OOM）。

### 验证
- `tc.new.exe.exe check/run examples/proj_demo/src/main.tc` → `hi from hello`/`5`/`110`，0 诊断。
- 回归 `agentkit_demo.tc`（`recorded frames=4` 等）、`module_hello`（hello from main/6/hello,world）均通过，新加 `t/src` 候选根无误命中。
- L0 gate：静态检查 PASS、自举一代 PASS、产物快照比对进行中（待结束）。

## 经验（下次别再踩）
- **gate 千万别放后台**：记忆里写过「管道静默挂起」，前台跑更可控。
- **`sb_catN` 实参必须 == N**，且 LLVM 后端不支持 `sb_cat2..6` → 多段拼字符串一律 `StringBuilder`。
- `eprint` 在 arena abort 时缓冲不刷出，死循环/OOM 现场看不到 → 排查路径分配类 bug 直接改逻辑而非靠 eprint 追踪。
- OOM 类 bug 优先「消除分配来源 + 硬上限」而非「加 guard 放行」——`guard>64` 看似有上限，但震荡里终止条件永不成立的死循环仍会跑满上限且每次都分配。

## 外部库「第六刀」：getenv 中性内建 + `--lib-dir` + tote 环境变量搜索（已落地全绿）

### 架构裁定（用户原话「环境变量搜索 getenv，这个是不是应该写入 tote」）
- **tc 不读环境变量**（架构红线：tc 只管 lex/parse/sema）。tc 只提供**中性原语** `getenv(name)->string` 与**中性输入开关** `--lib-dir <path>`；tc 自身的 `compute_lib_dirs` **绝不调用 getenv**。
- **策略归 tote**：tote 读 `T_LIB_PATH` 与 `~/.tote/libs`，解析后以多个 `--lib-dir` 传给 tc（类比 rustc/cargo 的分工）。

### 实现
- `src/tc.tc` getenv 五处注册：`builtin_ret`(→string)、`td_calls`、C emit(`t_getenv(t_cstr(x))`)、LLVM emit(`ll_scratch %TStr` + `call void @tll_getenv(ptr,ptr)`)、`llph` declare；外加 `infer_call` 实参类型校验(`T_ARG_TYPE`)。
- `runtime/t_runtime.c` 加 `TStr t_getenv(const char*)`（未设置返回空串，不返 null）；`t_runtime.h` 声明；`t_shim_ll.c` 加 `void tll_getenv(TStr* name, TStr* out)` 指针桥（避 Win64 聚合 ABI）。
- `src/tc.tc` 加 `--lib-dir <path>` 开关：追加进 `g_lib_dirs`（优先级最高，排在约定目录之前）。
- `src/tote.tc` 加 `split_path_list`/`home_dir`/`append_lib_dirs`，在 `cmd_build_or_run` 构造 tc 命令时注入 `--lib-dir`。

### 两个真 bug（本轮排查出）
1. **tote `str_concat3(hd, "/.tote/libs")` 少传一个实参** → tc **静默放行**，代码生成只 emit 2 个实参，第 3 个形参 `c` 未初始化 → `sb_append_str(sb, c)` 读到垃圾 len → 巨循环撑爆 512MB arena → `arena: out of memory`。⚠ **暴露编译器 sema 缺口：用户函数调用的 arity 未校验**（内建有 `T_CALL_ARITY`，用户函数没有）——待修。
2. **`split_path_list` 把 `:` 当分隔符** → Windows 盘符被误切：`C:/tmp/onlyenv` → `C` + `/tmp/onlyenv`，环境变量搜索实际失效。修法：只按 `;` 切（与 Windows PATH 语义一致）。

### 排查方法论（值得复用）
- arena OOM 时 `eprint` 缓冲不刷 → 但**分段打点 stderr** 仍可定位（本轮 DBG1..DBGf 逐级二分，精确落到 `str_concat3` 那一行）。
- **先证明"直接 tc 跑通"的那个用例是否真覆盖新特性**：本轮 `envdemo.tc` 只 `import @json`、**根本没调 getenv**，导致误判"getenv 已验证"。写最小复现时必须逐个还原真实调用链（getenv → home_dir → str_concat3）。
- 参数顺序、`~/.tote/libs` 是否存在、`.ll` 里 `ptr 0`(=UNSUPPORTED 占位)都是干扰项——`UNSUPPORTED` 只是因为测试文件里没定义那个函数。

### 验证
- 对照实验：库**只**放 `C:/tmp/onlyenv`，不设 `T_LIB_PATH` → `T_IMPORT_NOT_FOUND`；设了 → 打印 `FOUND_VIA_TLIBPATH`。委托命令为单个正确的 `--lib-dir "C:\tmp\onlyenv"`。
- `t_runtime.lib` 是**预编译产物**，加运行时符号后必须 `node tools/build_runtime.mjs` 重建，否则 tote 冒烟链接报 `tll_getenv` 未定义。
- gate L2 **13 passed / 0 failed / 0 warn**；IR 基线按「装 g4 → 用其 g1 重录」流程归零。
- docs/reference.md §3.13 新增第 10 条规则（环境变量搜索），四处「待 getenv 内建」状态标记已改为已落地。
