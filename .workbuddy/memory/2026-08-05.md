## 选项①收尾：修 path_exists + toml 自动定位工程根（src/tc.tc）

### 根因（OOM）
- `compute_src_roots` 旧 walk 在循环体内调用 `path_resolve(mod_dir_of(cur))`。
  `path_resolve` 走 `_fullpath`；走到盘符根 `C:` 时 `_fullpath("C:")` 把「C 盘当前目录」展开成
  `C:/Users/seesaw`，于是 `C:/` ↔ `C:/Users/seesaw` 来回震荡，`parent==cur` 永不触发，
  每次 `path_resolve`+`sb_cat` 都从 arena 分配 → `arena: out of memory`。
- 叠加：仓库根 `t/tote.toml` 存在，walk 一路爬到仓库根把 `t/src` 加进候选源码根，import 解析空间被污染。

### 修法（已落地并验证）

- `compute_src_roots`：入口目录仅一次 `path_resolve` 兜底；向上遍历用 `parent_dir_of`，硬上限 `guard<32`。
- 拼接改走 `StringBuilder`（`sb_new`/`sb_append_str`/`sb_to_str`），不用 `sb_cat2`。

## 外部库「第六刀」：getenv 中性内建 + `--lib-dir` + tote 环境变量搜索（已落地全绿）

### 架构裁定（用户原话「环境变量搜索 getenv，这个是不是应该写入 tote」）
- **tc 不读环境变量**（架构红线：tc 只管 lex/parse/sema）。tc 只提供**中性原语** `getenv(name)->string` 与**中性输入开关** `--lib-dir <path>`；tc 自身的 `compute_lib_dirs` **绝不调用 getenv**。
- **策略归 tote**：tote 读 `T_LIB_PATH` 与 `~/.tote/libs`，解析后以多个 `--lib-dir` 传给 tc（类比 rustc/cargo 的分工）。

### 实现
- `src/tc.tc` getenv 五处注册：`builtin_ret`(→string)、`td_calls`、C emit(`t_getenv(t_cstr(x))`)、LLVM emit(`ll_scratch %TStr` + `call void @tll_getenv(ptr,ptr)`)、`llph` declare；外加 `infer_call` 实参类型校验(`T_ARG_TYPE`)。
- `runtime/t_runtime.c` 加 `TStr t_getenv(const char*)`（未设置返回空串，不返 null）；`t_runtime.h` 声明；`t_shim_ll.c` 加 `void tll_getenv(TStr* name, TStr* out)` 指针桥（避 Win64 聚合 ABI）。
- `src/tc.tc` 加 `--lib-dir <path>` 开关：追加进 `g_lib_dirs`（优先级最高，排在约定目录之前）。
- `src/tote.tc` 加 `split_path_list`/`home_dir`/`append_lib_dirs`，在 `cmd_build_or_run` 构造 tc 命令时注入 `--lib-dir`。

### 两个真 bug（本轮排查出）
1. **tote `str_concat3(hd, "/.tote/libs")` 少传一个实参** → tc **静默放行**，代码生成只 emit 2 个实参，第 3 个形参 `c` 未初始化 → `sb_append_str(sb, c)` 读到垃圾 len → 巨循环撑爆 512MB arena → `arena: out of memory`。⚠ **暴露编译器 sema 缺口：用户函数调用的 arity 未校验**（内建有 `T_CALL_ARITY`，用户函数没有）——待修。

## 第二个编译器 bug：直接调用具名函数不校验实参（已修全绿，待提交）

### 根因
- 直接调用 `f(x)` 时，`infer_expr` 命中 `fd.kind=="FuncDecl"` 分支**只 return 返回类型，完全不校验实参个数与类型**；代码生成只 emit 实际传入的实参，少传的形参在函数体内读到未初始化的栈槽。若该形参是 `string`/`[]T` 的 `len` 字段 → 随机天文数字 → 循环撑爆 512MB arena（`arena: out of memory`），且报错离真错误点极远。tote 的 `str_concat3(hd, "/.tote/libs")` 少传一参正是此坑（第六刀排查出）。

### 修法（src/tc.tc，未提交）
- `check_indirect_call` 改名 `check_call_args(e, fti, fname)`，直接/间接调用共用：加 `fname` 参数用于报错显示 `调用 `name`` vs `间接调用`；元数不符 `fc_err("T_CALL_ARITY", ...)`；逐位 `infer_expr` + `ti_equal`/`can_cast` 不符报 `T_TYPE_MISMATCH`。
- 直接调用路径接入：`if (fd.kind=="FuncDecl") { check_call_args(e, s2.ti, fname); return resolve_ti(fd.na); }`。
- 兜底补扫：内建实参「按需」推导会漏掉嵌套其中的用户函数调用（如 `println(int_to_str(add3(1,2)))`），在 `return builtin_ret(fname)` 前对 `n.la` 所有子节点再 `infer_expr` 一遍；重复推导由 `diag_new` 去重兜住。
- `diag_new` 加线性去重：同 (code, file, sl, sc, msg) 返回已有索引，避免兜底补扫产生成对重复报错。
- `ti_equal` 修复：新增 `is_user_named_kind`，让 `Named`（resolve_ti 类型注册前产出的未解析引用）与已解析的 `Struct`/`Enum`/`Flag`/`FlagSet`/`Union`/`Variant` 按 name 判等，跨模块同类型不再因解析时机不同误判不等（修 `agentkit_demo` 误报 `T_TYPE_MISMATCH`）。
- variant 合成助手（`Name_from_Case`/`Name_is_Case`/`Name_as_Case`）经 `register_variant_helpers` 直接 `sym_define` 裸 Func tip、未走 `register_decl` 填 `tif_pstart`/`tif_pcount` → `tif_pstart[fti]==-1`；`check_call_args` 加 `if (pstart<0) { return; }` 守卫，绝不用 -1 索引 `tif_params`（修 `p08_variant`/`p34_fmt_method` 的 `index_out_of_bounds`）。

- 用户拍板主线下一步 = **llm_boundary 真 LLM**：把示例里的 `fake_llm` 桩换成真实 LLM 调用的 `drive_*` 适配器（sidecar 旁路桥，零编译器改动）。

### 实现
- 新增 `examples/lib/llm_boundary.tc`（`export drive_llm(prompt: string) -> string`）：stdin/stdout 旁路桥协议——`println("LLMREQ|"+prompt)`+`fflush(stdout)` 出，`stdin > string` 逐 token 读到 `__EOM__` 空格重拼回。作为 `@llm_boundary` 外部库被示例 import（与 json/csv 同模式）。
- 重构 `examples/agent_npc_mind_llm.tc`：删内联 `llm_local`，改 `import @llm_boundary;` + `llm_boundary.drive_llm(prompt)`。
- 增强 `tools/llm_bridge.py`：`call_local_llm` 按 `LOCAL_LLM_MODE` 分支——默认 `ollama`（本地 `/api/generate`）；新增 `openai` 模式走 `/v1/chat/completions`（需 `LOCAL_LLM_KEY`，`LOCAL_LLM_URL` 可覆盖）；不可达一律回退确定性应答（`fallback_llm`：prompt 含 "hours" → "We are open 9 to 5."）。仅用标准库。

### 验证
- 构建 `out/dbg/npc_llm`（注意 `--output` 不带 `.exe`，否则产 `npc_llm.exe.exe`）→ `python tools/llm_bridge.py out/dbg/npc_llm.exe`。
- 端到端（无 Ollama 走回退）：`:talk`+"hours" → `LLMREQ|hours` → 桥回退 → `after talk-> ... last=We are open 9 to 5.`；`:use_door`+"door" → `last=door opened`；exit 0，管道不死锁（fflush + __EOM__ 握手正确）。
- OpenAI 模式无 key：`LLM 不可达（LOCAL_LLM_MODE=openai 但 LOCAL_LLM_KEY 未设置），回退确定性应答` → 仍 `last=We are open 9 to 5.`，证明分支可达且优雅降级。
- IR 基线漂移：baseline 含 `examples/agent_npc_mind_llm.tc` 作 target，重构示例改变其编译产物 → 预期 WARN → `ir_snapshot.mjs --compiler out/dbg/g1.exe --update` 重录 → gate L2 **13 passed/0 failed/0 warn**。
