## 进一步说明:接线式(Wiring form)去耦方案(用户要求深化说明、未落地)

- **本质**:接线式不是新增编译器能力,而是把「inline 糖衣」反过来写成「引用已声明符号」。两种写法脱糖到**完全相同**产物(CounterState struct + counter_step fn + counter_spawn fn),后端零改动。`agent { use XState; use x_step }` 只负责命名「谁+谁构成 agent」,解声明层耦合。
- **spawn**:仍自动合成,参数表 = 被 use 的 struct 字段按声明顺序(与今天由 state 列表推导同源)。
- **inline 做不到、接线式能的三复用**:① 状态复用(MonsterState 被多个 system 操作)② 系统复用(一个 step 接多个 agent)③ 批量 ECS(直接对 []State 切片跑 system,无需任何 agent 对象——数据导向本色)。

## 用户回拨:接线式使 Agent 更复杂 → 收敛到最小核(重要设计转向)

- **用户原话**:接线式导致 Agent 越来越复杂,问「好方案 + 还记得为什么引入 agent 吗」。
