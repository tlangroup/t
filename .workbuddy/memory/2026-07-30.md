### 本轮踩坑铁律（t 语言语义 + tote 内部约定）
1. **slice 是值传递** —— 函数内 `append` 不影响调用方。字段表/JSON 键值表一律改用**全局 + base 偏移**（`imp_fnames`/`imp_ftypes`/`imp_fbase`、`jp_keys`/`jp_vals`），同 `fr_names`/`fr_starts` 手法。误用 out 参数的表现是 `t_slice_at index 0 length 0` 越界 panic。
2. **`sb_append_u8` 不存在**，正确内建是 **`sb_append_char`**。前者在 LLVM 后端**静默**发射 `; UNSUPPORTED call sb_append_u8`（不报错），表现为字符串构建结果全空。排查手法：`grep -o "UNSUPPORTED call [a-z_0-9]*" x.ll | sort | uniq -c`。
3. **合成 FuncDecl 的 `ba`(is_extern) 必须为 false** —— 传 true 会让 emitter 只发 `declare @f()` 不发函数体，链接期报 `use of undefined value`。对照参照点：parser 在 L5458 传的是真实 `is_extern`。
4. **合成的 decl 必须 `append(decl_list, fn)`**，否则 emitter 遍历不到；且 `run_check` 的 check 循环要**重取 `slice_len(decl_list)`**（原代码复用 register 循环的 `n`，会漏检新增项）。
5. **自举鸡蛋问题**：新增内建要在 tote 自身运行期生效，必须**两阶段自举**（canonical→tote_b，tote_b→tote_c）。只做一阶段时 canonical 不认识新内建，把调用发射成 UNSUPPORTED，返回值恒 false —— 本轮 `file_exists` 误报 T_IMPORT_IO 即此因。
6. string 的 `+` 在 LLVM 后端未实现（发射成 `add i64 @.tsN, %sM`），一律用 `cat2`/`cat3`。
