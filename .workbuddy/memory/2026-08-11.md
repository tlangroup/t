## REPL 语句形态 bug 修复（用户报 `(1..10) |> |v| print(f"{v}");` 过不去）

### 现象
- 用户在 REPL 输入 `for`/`if`/块语句时，报 `T-PAR-E101 unexpected token in expression: ;`（落在语句后多余 `;`）。
- 根因有两层：

### 根因 A（语法认知，非 bug）：`t` 的 lambda 不是 `|v| ...`
- `t` 闭包语法是 `fn(name: Type) Ret { body }`（parse.tc:1060 `裸 fn 即 lambda`），`|v|` 会被词法切成 `|` `v` `|` 三个 token，解析器在表达式里撞到裸 `|` 直接报 T-PAR-E101。
- 管道 `|>` 是「整体应用」（lower_pipe 多态分派整体优先），不是逐元素迭代；`|->` 才逐元素但要求右函数非 void 返回（T-PIP-E869）。
- 所以「遍历 1..10 打印每个」在 `t` 的正确写法是 `for (i in 1..10) { print(f"{i} "); }`（注意 `1..10` 半开，到 9；要含 10 用 `1..=10`）。

### 根因 B（真 bug）：REPL `sform` 对每条语句无条件补 `;`
- `src/repl.tc:231` 旧：`sb_cat4(decls, "...\n    ", tsrc, ";\n    return 0;\n}\n")` —— 无条件追加 `;`。
- 后果：块语句 `for (i in 1..10) { ... }` 被包成 `for (...) {...};`，而 `t` 里 `};`（块语句后跟 `;`）是非法语法 → T-PAR-E101。文件编译同样：`for (...) {...};` 报错、`for (...) {...}` 正常。
- 注意：vform（值形态 `format("{}", <input>)`）先试，块语句在其内非法会先失败，再落到 sform；修复只动 sform 即可。

### 修复
- `src/repl.tc:231` 改为复用 `repl_term(tsrc)`（repl.tc:100 已有：末字符非 `;`/`}` 才补 `;`，已覆盖块语句与用户自带尾 `;` 两种情形）：
  `sb_cat4(decls, "\n__repl_eval fn() i32 @main {\n    ", repl_term(tsrc), "\n    return 0;\n}\n")`
- 顺带消除旧 note 里的「输入带尾 ; 会变 ;;」坑（repl_term 幂等）。

### 验证（g1.exe 实测 REPL）
`for (i in 1..10) {...}`→`1..9`、`print("hi")`→`hi`、`1+2`→`3`、`if (true) {...}`→`yes`、`print("hi");`(自带尾;)→`hi`，全部正常。

### 收尾
- 修复后跑 `gate.mjs L2` 确认无回归、产出可升级 g4；再 `cp g4.exe tc.exe`。

## REPL 新增 `ans` 特殊变量（保存上一条输出）

### 需求
- 值打印已存在（vform: `println(format("{}", <input>))`），`1+2`→`3` 基线正常。
- 新增 REPL 特殊变量 `ans`：保存**上一条表达式/语句的输出**（字符串）。选 `ans`（MATLAB 风格）而不用 `_`，因 `_` 是 `t` 的 match 通配符，避免冲突。

### 实现（src/repl.tc）
- 每条 REPL 输入是全新子进程，跨进程无状态，故 `ans` 由**宿主进程**持有：每次成功求值后捕获 stdout（`repl_run` 改为返回 outc），存入 `last_out: string`；生成下一份 snippet 时前置 `var ans: string = "<escape(last_out)>";`（仅注入本次生成的 snippet，不污染会话 decls）。
- 新增 `repl_escape_str`：把上一条输出转义为合法 t 字符串字面量（先转 `\`→`\\`，再 `"`→`\"`、`\n`→`\n`、`\r`→`\r`），避免输出里的引号/反斜杠破坏注入字面量。
- `:reset`/`:load` 清空 `last_out`；声明形态（dform）成功不更新 `last_out`（保留上一条 ans）。
- `:help` 增加 `ans` 说明行。

### 验证（g1.exe REPL 实测）
- `1+2`→`3`；`ans`→`3`；`for (i in 1..4){print(f"{i} ");}`→`1 2 3 `；`ans`→`1 2 3 `；`print("hello ")`→`hello `；`ans`→`hello `。
- 转义往返：`print("a\\b")`→`a\b`，`ans`→`a\b`；`print("he said \"hi\"")`→`he said "hi"`，`ans`→`he said "hi"`（经 Write 工具造含 `\\` 的输入文件 + `cat` 管道，避 Bash 工具把 `\\` 压成单反斜杠的干扰）。

### 收尾
- `gate L2`：首跑 14 passed/0 failed/1 warn（仅 src/tc.tc 自身 IR 差异，57 示例零变化，预期）；重录基线后复跑确认全绿；`cp g4.exe tc.exe` 升级（注意残留进程锁，先 taskkill）。
- ⚠ Bash 工具（printf/heredoc）会把 `\\` 压成单 `\`，涉及反斜杠的 REPL/源码测试须用 Write 工具造文件 + `cat` 管道喂入。

## `|>` 逐元素 + void lambda 降级 for-each（用户选「加简写 + 让 |> 逐元素」）

### 目标
支持 `(1..10) |> |v: i64| print(f"{v} ");` 这类写法：`|>` 在右侧一元函数返回 void 时，逐元素应用**合法降级为 for-each 副作用遍历**（等价 `for (v in 1..10) { print(v); }`）。`|->`(map)/`|>?`(filter) 返回 void 仍报 T-PIP-E869。

### 解析 / 语义（上轮已落地，本轮验证存在）
- `parse_bar_lambda`（parse.tc:1099）：吃掉起始 `|`、可选 `(`、解析 `name: Type` 形参、吃结束 `|`、读主体表达式、包成 `{ return <expr>; }`、返回类型填 `mk_infer_ret()`（返回类型待推断占位）。
- `infer_lambda_ret_from_decl` / `infer_scan_return`（sema.tc）：扫描 return 推断 lambda 返回类型（t 函数返回类型本无推断，此特性补齐）。
- `lower_pipe` elemw 分支（sema.tc:2759）：`prt1==Void && pkind=="pipe_apply"` → 冲刷累积阶段后 `mk_for_each(fevar, "", cur_e, feblk)` 生成 for-each。

### 本轮修的发射层三处 bug（根因：for-each 不当表达式发射）
1. **sema.tc expr 语句处理器**：`lower_pipe` 把管道根就地改写成 `block`（内含 for_each），但父级 `expr` 语句仍走 `emit_expr(n.na)` → `/* unsupported expr */`。修复：infer_expr 后若 `nodes[n.na].kind=="block"`，把本语句整段改写成 `block` 语句并递归 `check_stmt`（沿用 lower_for_range 的语句级改写套路），让 for_each 走正常 `check_stmt` 路径（注册循环变量、递归 body）。
2. **codegen_ll.tc for_each 处理器**：循环变量只注册进 `lla_n`(alloca 表)，未 `fs_set(em_cur_fn, n.sa, etd)`；`emit_lle` 的 ident 分支只查 `fs_get`，查不到 → 返回 "null" → 被强转成 `i64 0`（lambda 被传常量 0）。修复：slice 分支 `fs_set(em_cur_fn, n.sa, etd)`、map 分支 `fs_set` key/val 类型（与 codegen_c 的 collect_local_types 对称）。
3. **codegen_ll.tc return 处理器**（line 3153）：`rty=="void"` 时直接 `ret void` 并**丢弃 n.na** → `return print(...);` 在 void 函数里啥也不做。修复：`rty=="void" && n.na>=0` 时先 `emit_lle(n.na)` 保留副作用再 `ret void`。（C 后端 `return <void-expr>;` 本就合法，无需改。）

### conformance 测试调整（行为变更）
- `f95_pipe_void_map.tc`：原 `xs |> show`（apply void）现合法（降级 for-each），改为 `xs |-> show`（map void）保留「void 映射禁止」断言，仍 EXPECT error T_PIPE_VOID_MAP(=T-PIP-E869)。
- 新增 `p49_pipe_apply_void_foreach.tc`：覆盖 `xs |> show` 与 `(1..10) |> |v: i64| print(f"{v} ")` 两种合法 for-each 降级，EXPECT pass。

### 验证
- `tmp/bar1.tc` `(1..10) |> |v: i64| print(f"{v} ");` 双后端均输出 `1 2 3 4 5 6 7 8 9`（LLVM run + C: clang 编 runtime/t_runtime.c+runtime/t_shim_ll.c 运行）。
- REPL（升级后 tc.exe）实测：`1+2`→`3`、`(1..10) |> |v: i64| print(f"{v} ");`→`1 2 3 4 5 6 7 8 9`、`ans`→回放上条输出。用户原句 `|v: i32|` 也工作（can_cast 允许 i64→i32 收窄，1..9 无损）。
- ⚠ 限制：裸 `|v|`（无类型标注）仍报 T-PAR-E101——t 要求函数形参显式类型，本特性只推断**返回**类型，未做形参双向推断；`|v: T|` 写法符合用户选择。

### 收尾
- `ir_snapshot.mjs --compiler out/dbg/g1.exe --update` 重录基线（3 处 IR diff 来自 #2/#3 修复，run_examples 双后端全过证明零行为漂移）。
