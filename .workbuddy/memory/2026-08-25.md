## Notebook 编译环境路线裁定 + docs/notebook.md
- 决策：tc 保持 oblivious（不改语法/语义）；notebook = 构建在 tc 之上的编排层。每 cell 一个独立 `.tc`；声明 cell → `tc build --lib` 出 `.tlib`，表达式 cell 包装为模块级 `var <cellId> = E`，下游 `import(id :: *)` + `--lib-dir`。
- 执行目标：原生子进程优先（阶段1），wasm32-wasi 阶段2（仅宿主包装 + runtime 去 Windows 头，不改前端/codegen）。
- 跨 cell 值桥（头号障碍）：MVP 走零改动文件协议 `fid <>` + `@derive(BinarySerde)`；增强方案 `to_value` 内建属通用能力（走 design.md 提案，非 notebook 专属）。
- 调研已核验基石：`@derive(BinarySerde)`（codegen_c.tc:2523）、`emit-ll` 不要求 main（tc.tc:345/357）、`build --lib` 跳过进程级全局发 `.tlib`（tc.tc:310/349）。REPL 的"整会话重编+文本 ans"模型不可复用（丢状态/结构），但其干净子进程编排范式可复用。
- 交付：`docs/notebook.md`（路线 + 架构 + cell 包装 + 值桥 + 缓存/DAG + 诊断 + WASM + 障碍清单 P0/P1/P2 + 三阶段计划 + 红线治理）。
- 用户二次纠正（已回写文档）：① WASM 两条可选路线——前期 IR→轻量LLVM(无外部LLVM依赖)→wasm 二进制；后期 IR→LLVM-IR→opt/llc→wasm。轻量 wasm codegen 属通用后端能力（非 notebook 专属，走 design.md 提案）。② 编译单元语义：t 每 `.tc` 文件即一个 module；跨 module 不能直接调函数，须走 import 语法；机制后期会变，设计只依赖"模块导入"稳定契约，不硬编码当前 import 细节。
