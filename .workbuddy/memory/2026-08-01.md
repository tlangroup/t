## M44（2026-08-01）语法精简：移除 `::` 绑定符 + `func` → `fn`（用户指令「1&2」）✅

顶层声明从**绑定式** `Name :: func(...)` / `Name :: struct {...}` 全量迁移为**并置式** `Name fn(...)` / `Name struct {...}`；typealias 从 `Name :: Type;` 变为 `Name Type;`。依据 `docs/laws/general.md` L-01 第19条 (a)「输入最小化」。波及 79 个 `.tc`、1565 处声明。

### 桥接自举策略（关键设计，可复用）
语法不兼容期无法一步切换（改了源码旧编译器编不了，改了编译器新语法还没写）。三段式跨越：
1. **Phase 1 桥接**：编译器同时接受新旧两法——词法器加 `kw_reg("fn","KwFunc")` 别名（暂留 `func`），`parse_declaration` 的强制 `::` 改为**可选**。用旧 canonical 编译**旧语法源码** → `tc_bridge.exe`（新旧通吃）。
2. **Phase 2-3 迁移源码**：`build/migr/migrate_syntax.py` 正则批量改写全部 `.tc`（支持 Unicode 标识符 `主函数`、`comptime` 前缀；负向后视排除 `"func"` 字符串与 EBNF 产生式分隔符）。用 `tc_bridge` 编译新语法源 → `tc_x.exe`。
3. **Phase 4-5 收紧**：编译器删 `func` 关键字、`::` 改为**带迁移指引的硬错误**，重新自举至不动点。

### 实现要点
- **`fn` 成关键字后与既有标识符冲突**：`src/tc.tc` L8584 `var fn: i64`→`fdecl`（活跃编译器必改）；`src/checker.tc`/`src/parser.tc` 各 13 处 `var fn: Node`→`fnode`；`src/totter.tc` 参数 `fn`→`col`；`gen/tc.tc` L8152 同 `fdecl`。**新增关键字前必须全库扫同名标识符**。
- **迁移错误必须友好**（L-01 第19条）：`Name :: func(...)` → `parse error: the '::' binder was removed; write \`Name fn(...)\` / \`Name struct {...}\` instead`；`Name func(...)` → `parse error: keyword 'func' was renamed to 'fn'; write \`Name fn(...)\` instead`。带具体名字，而非泛化的 "expected Semicolon but found (".
- **`@derive` 字符串模板**（src/tc.tc L11278 等）内嵌的 `:: func` 也须改（生成的是源码文本）。

### ⚠ 踩坑：门禁工具正则失配导致「假绿」
`tools/shadow_check.mjs` L10 的 `fnStart = /^(\w+)\s*::\s*func/` 迁移后**匹配不到任何函数**，却仍打印 "OK" —— 是**零样本假绿**。改为 `/^(?:comptime\s+)?([\p{XID_Start}_][\p{XID_Continue}_]*)\s+fn\s*\(/u` 后恢复 439 个函数头全覆盖。**教训：改语法后必须核对所有正则型门禁工具的匹配数，"OK" 不等于"检查过"。**

### 结构性后果：tc0 对拍通道失效
