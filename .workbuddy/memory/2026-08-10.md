### 本轮踩到并修掉的四个坑（都值得记）
1. **词法错误被 parse 硬中断盖掉**。E003/E004/E008 明明 `diag_new` 了，但坏 token 流让 `parse error:` 先 `exit(1)`，诊断永远看不到。解法：`tokenize()` 后加**阶段闸门** `if (has_errors()) { print_json(); return 1; }`，四处入口全加（`src/tc.tc` 三处 + `src/test.tc` 的 `run_test_cmd`）。这是通用规矩，不止本次。
2. **`#include <math.h>` 污染名字空间**。为 `INFINITY`/`NAN` 加了 math.h，结果 libc 的 `yn`（Bessel 函数）与 `examples/fid_error_demo.tc` 的用户函数 `yn` 撞名，3 个示例 C 后端编不过。⇒ **C 后端前导 include 是全局污染面，能不加就不加**；改用 `__builtin_inf()` / `__builtin_nan("")`（无头文件，clang/gcc 通吃，C 后端本就只面向 clang）。
3. **LLVM `fcmp one` 对 NaN 是错的**。`!=` 原本发 `one`（ordered ≠），`nan != nan` 返回假，与 C 后端的 `!=` 不一致。IEEE-754 下 `x != y ⇔ !(x == y)`，必须用 **`une`**。这是被 NaN 暴露出来的既有缺陷，其余关系运算保持 ordered。
4. **`-inf` 常量折叠产非法 IR**。`ll_unary` 的 `-` 会给常量文本加前缀，`-0x7FF0000000000000` 被 IR 解析器判成「整数常量用于浮点类型」。须在折叠前拦截 float 节点的 inf/nan，直接给取反后的位模式。
- 另：新 `var w0: u64` 与 `tokenize` 里既有 `var w0: i64` 撞成异型 → `shadow_check` 抓到，改名 `sfx0`。**先跑 `shadow_check` 再跑 gate 省一轮。**
